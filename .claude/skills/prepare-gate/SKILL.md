Prepare Gate 1 for the explicit item: $ARGUMENTS
Consult [gates](../../../docs/workflow/gates.md) and relevant MC entries. Obtain a targeted investigator packet covering actual trigger/mechanism, load-bearing source/runtime premises, endpoints/subsystems, smallest coherent boundary and viable stages. Hand the packet path to the designer for the proposed plan and required tests. Settle decision-critical user-visible skip/repair/refuse/pause branches with the maintainer when source cannot decide the product trade-off. Unresolved decisions block dependent work only. After sizing and before Gate 1, run the grilling step (`MC-778`): an independent agent other than the designer reads the sizing and the draft plan and lists every product or error-behaviour ambiguity, each with a recommended option; drop what existing MCs already settle, and ask the maintainer the rest with AskUserQuestion, recommended option first; have the designer finalise the plan with the answers. Provide requirements, invariants, acceptance scenarios, risks and target-specific verification to an independent reviewer; expensive-to-reverse plans receive advisor challenge. Keep the tiny low-risk carve-out and avoid speculative exhaustive edge inventories. This action does not authorize implementation beyond the user's scope.
