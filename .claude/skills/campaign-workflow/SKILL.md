Carry out the explicit task: $ARGUMENTS
Consult [workflow README](../../../docs/workflow/README.md), [routing](../../../docs/workflow/routing.md) and [gates](../../../docs/workflow/gates.md) as needed. Start with relevant authority/MC entries, then separate discovery, implementation, independent review and arbitration contexts. Read `.claude/workflow-policy.json` and `Agents/Workflow-State.json`; routing is native first (MC-2748, [routing](../../../docs/workflow/routing.md)): a fresh native role by default, Codex or Antigravity only as an `optIn` dispatch after a passed route-health check under 7 days old, which the controller enforces (#387; see routing.md); routine supplied-evidence records go to the native Haiku `record-clerk`. Size the work first ([gates](../../../docs/workflow/gates.md) size tiers, MC-2746). Use tiny inline lookups and bounded leaf delegation. Preserve combined batch gates, accepted receipts/applicability, one-correction lineage and parked device checks across stage/provider/context changes. Apply the task's actual authorization; this skill does not authorize unrelated edits, publishing or git commits. Subagents hand back a three-line pointer to their report file; read the file selectively.
For Tier 2 work (MC-2746), before Gate 1 obtain targeted mechanism/size evidence: trigger, load-bearing source/runtime premise, affected endpoints/subsystems, smallest coherent shared-cause correction and viable stages. Settle decision-critical user-visible skip/repair/refuse/pause choices. Missing product decisions block only the dependent plan/implementation; continue independent work. Do not inventory speculative rare edges. Tier 0 and Tier 1 work needs no sizing packet or designer; for Tier 2, after sizing the designer writes the plan and required tests and every Gate 1 revision; the orchestrator routes and does not author them.
Produce the concrete requested result and actual verification evidence. Technical acceptance does not make it COMPLETE: COMPLETE is the MC-2747 definition in [records](../../../docs/workflow/records.md) (PR merged, issue closed with a link, board card moved, every leftover dispositioned). Independently verify changed record claims incrementally; no automatic Gate 2 restart for administrative/editorial closure.
Apply [ownership](../../../docs/workflow/ownership.md): one application-code writer per checkout, including tests; disjoint named documentation writes and read-only helpers may run concurrently. One session per ticket, each with its own worktree from a verified explicit base, `claude/<ticket>` branch and PR; caps live in `.claude/workflow-policy.json`. Device waits and record closeout are not global barriers. Serialize actual overlapping ownership/resources, shared builds and invalidating benchmark load only. Preserve pinned device artifacts/frozen record packets. Commit, push, PR open and merge follow the approval matrix in [gates](../../../docs/workflow/gates.md#approval-matrix-mc-2744) (MC-2744); destructive cleanup is always asked.
