Date 2026-10-26. Observations from source and prior check records only. Nothing was re-run in a browser for this note. Verdicts in section 4 are proposals for the design author. Context: DS-003 (`settings/DECISIONS-settings.md:21`) = build on N09/N10, restyle in chat-slice conventions; DS-001 pain points = long preset lists, preset shortcut limited to first 10, no organising of prompt presets, hard to find settings, confusing model setup, opaque parameters.

## 1. What the mockups contain

### 1.1 N09 Settings (`settings.html`)

- **Screen model:** one "Settings" view plus a stub "task" view (`#task`, settings.html:161) used to demonstrate Back to task / Open Settings with a preserved unsent draft (N09.1). Header: Back button, h1, crumb "Returning to ...", search box, chip "Synthetic preview: nothing is saved" (:136-145).
- **Navigation model:** left index of 14 sections in 6 groups (SECS, :177-192): Basics (General, Models and prompts), Preferences (Reading and appearance, Language and translation, Interaction and accessibility, Keyboard shortcuts, Modes and features), Content (Identity and loadouts, Extensions and tools), Advanced (Custom interface builder, Custom sidebar, Data and backups, Advanced), Help. Five rows are stubs that name their owning mockup (General, Models, Identity, Data, Advanced, Help; `stub:` fields). Built pages: reading, language, interaction, hotkeys, modes, ext, gui, sidebar.
- **Layout and breakpoints (CSS :100-123):** shell is index + detail + preview at >=1280 (preview sticky when height >=880); 1024-1279 index + detail with a Show/Hide preview toggle; below 1200 the GUI builder gets a Structure/Properties/Preview tablist; below 720 index and detail replace each other with Back to Settings (`is-detail` class), preview hidden behind its toggle. Four tested widths: 1440, 1024, 390, 320.
- **Controls:** a data-driven `DEFS` table (:194-213) of 5 control kinds: select (`sel`), toggle (`tog`), stepper (`step`, text size 80-200 in 10s), plus custom pages. Each def carries `scope` chip (All chats / Default for new chats / This device / This chat / "Scope to confirm") and `apply` timing (now/next), keywords `kw`, and an optional before/after example `ex`. 15 defs: layout, text size, font, theme, text colour, background, notifications, motion (system/reduce/full), low power, reduce transparency, app language, translation provider, chat language, send behaviour, swipe gestures, message action visibility, editing style, larger touch targets.
- **Apply model:** no global Save. Each change shows "Applied in this preview" with Before/After and a Revert; focus stays on the control. Preview pane is a synthetic chat with a try-sending composer (Enter vs Ctrl+Enter, IME guard `isComposing`/229 in code only).
- **Search (:326-351):** AND of whitespace-split terms over name + keywords + group + group name; results replace the index, each result shows name and "group - scope", activating focuses the labelled control (`openCtl`). Section pages are also result entries (fix for review finding 7). No-results block offers Clear search and Browse settings. Esc in a non-empty search clears it (:692). Live-region count announcements.
- **Key handling:** Hotkeys page (HK0, :214-218): 8 named actions with capture mode (Change; Esc cancels; plain letter rejected with reason; conflict dialog Reassign / Keep old key; Tab away ends capture). Phone or narrow width (<720, width-based not touch-based) shows a read-only reference table. Document keydown (:689) handles Esc back-navigation. Roving/arrow keys for the tablist.
- **Modes page:** 4 modes (Utility, Roleplay, Hybrid, Playground), hide-unused toggle, last visible checkbox disabled, "Show all modes" review dialog, switch-mode unsent-draft warning dialog, OPEN note for Hybrid-only.
- **Builder / sidebar:** tree (GUI0, :220-223) with Add/Duplicate/Remove/Restore, container/component properties, dirty guard (Stay / Save draft / Discard; `guard()` :361). Sidebar list (SIDE0, CATALOG) with Move up/down, Add, Remove, unavailable item state, empty state.
- **Extensions page:** plugin-defined settings cards (PLUG, :226-229): toggle/select/text only; per-card failure with Retry; failure is isolated from the index.
- **Provider variants (OpenRouter / NanoGPT):** none in N09. They live in N10.
- **Fixtures (FX, :230-243; `?fixture=`):** default, search-no-results, large-text, long-labels, font-unavailable, notification-denied, hotkeys-phone, custom-gui-dirty, sidebar-empty, plugin-setting-failed, restore-modes, all-modes-hidden-repair. Unknown name falls back to default. Extra params: `?from=home|conversation` sets the Back target (`home.html?mode=<m>`, roleplay -> `rp`); `nonav=1` is a test aid.
- **States covered:** search empty, font fallback, image-fail fallback, notification permission denied, large text 200%, long labels, motion system/override, flat/low-power classes, forced-colors rules (:124-131), dirty exit, plugin failure, hidden-modes repair.

### 1.2 N10 Models and prompts (`models-and-prompts.html`)

- **Screen model:** two views: `host` (a synthetic task screen with a blocked Run and a "Set up a model" / "Model: X - change" button `#open-n10`) and `n10` (the editor). Header shows preset and connection chips. Banner keeps the task draft and the reason it cannot run (`reason()` :213-219).
- **Navigation model:** five tabs, `TABS` (:296): Connections, Models, Parameters, Prompt, Auxiliary AI. At <=440 px the tab row becomes a `Section` select (CSS :61); at <=700/720 list/detail panes replace each other with Back. Esc unwinds one level at a time (picker, editor, compare, detail, then host).
- **Connections:** list (4 synthetic: custom proxy, local, subscription-usage provider, router) + detail (provider kind, URL, masked key with Show / Replace, request format, simulated Test, Advanced fields). Variants selected by `kind` (:148-153): `usage` (NanoGPT-like: Usage / Endpoint and model / Connection views; subscription vs credits endpoint; Loading / ok / Out of date / Info unavailable; Refresh; Inactive subscription note; endpoint-model-unavailable requires explicit Replace) and `router` (OpenRouter-like: Connection / Routing / Instruct format; fallback, middle-out, ordered provider rows with Up/Down/Remove, Only and Ignore groups with a named conflict alert; instruct template editor with dirty dialog). Provider names are synthetic (Demo A-D, `.invalid` hosts, fake key `fake-key-0000-0000`).
- **Models:** filterable listbox (ArrowDown from filter, aria-activedescendant), details pane (context, capabilities, unsupported-parameter list), selection stays visible when filtered out; catalog states Loading / Empty / Failed / Local unavailable with Retry, manual model ID and "Use Local model instead"; long model ID wraps.
- **Parameters:** `PARAMS` (:116-122) temperature, top P, top K, max tokens, frequency penalty, reasoning effort; Main vs Auxiliary override rows; conflicting values with the chosen model are named and kept, not deleted.
- **Prompt / presets:** preset library with New, Duplicate, Import, Export (simulated outcome dialogs), Delete (blocked on last preset with reason), Compare (changes-only vs all, unified vs split; split disabled at 320; "No changes" valid result; +/- marks with screen-reader prefixes), ordered prompt blocks with Edit / Up / Down plus HTML5 drag, token estimates vs budget (labelled not provider billing), Add block, "View prompt structure" modal, block editor with its own dirty state, preset draft bar (Save preset / Discard). Only two presets in fixtures; there is no preset search, folder, pinning or shortcut slot UI (relevant to DS-001).
- **Auxiliary AI:** AUXF (:125-132) Memory, Voice, Emotion/image selection, Image generation, Translation, plus Easy panel requirements (before/after table; simulated failure lists changed / not changed / unknown). Off vs Missing config states.
- **Fixtures (FX, :134):** 22, listed in `evidence/models-prompts-checks.md:13`. Params: `fixture`, `view=host|n10`, `from=home|conversation|task-detail`, `return=<same-folder .html>` (validated, hostile values fall back), Home hand-off draft parked in sessionStorage under Home's key.
- **Key and focus rules:** originating button `#open-n10` always receives focus on return; Retry/Refresh/Test use aria-disabled + aria-busy and a polite live region; reorder announces "Moved X to position n of m"; focus keys `data-fk` survive full re-renders (`renderN10` :297-305, innerHTML rebuild).
- **Search:** only the model filter. No cross-page search.
- **Motion:** none defined in the page; relies on shared `prefers-reduced-motion` clamp (workspace.css:45). Usage-loading fixture auto-resolves after about 3.5 s via timer.
