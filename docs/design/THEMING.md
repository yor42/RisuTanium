# Theme-ready mockups

Standing rule from 2026-10-27 ([DD-142](DECISIONS.md)). Source: the maintainer's theme-pack direction, relayed by Lane A (MC-689, MC-691, MC-692, MC-695). Reference, read-only: `C:\Projects\RisuAI\Agents\Theme-Packs.md` (the 17 ideas, the capability matrix and the pack rules).

The mockups here are **Deep Nexus**, the baseline look that theme packs are defined against. A pack is tokens plus part-scoped CSS, with no free CSS. Packs change appearance, never behaviour.

## Rules for every mockup

1. **Tokens only.** Every colour, font, corner radius, spacing value, shadow, blur/transparency, motion value (duration and easing) and geometry value (box sizes, offsets, transforms, touch targets, gradient stops) comes from a named CSS custom property ([DD-143](DECISIONS.md)). A literal value in a component rule is a defect, except for 0, 1px hairlines and percentages used for layout math.
2. **Stable part names.** The main surfaces carry a `data-part="<area>-<name>"` attribute that a pack can target, for example `chat-header`, `chat-message`, `chat-message-body`, `chat-composer` and `settings-row`. Names describe a role, not a look. They don't change once published. Keep the list in the screen's spec. State a pack may style (first or last in a run, names hidden, touch or hover input and the like) is mirrored as `data-*` attributes on the part or the root, not only as classes ([DD-144](DECISIONS.md)).
3. **Critical surfaces take tokens only.** Packs may not restyle the structure of warnings, data-loss and save-failure prompts, permission dialogs, or restore and export dialogs. Mark them `data-part-critical`.
4. **Fallbacks.** Anything a pack could blur or make transparent needs a reduced-effects path; reduced motion already applies.
5. **Behaviour is fixed.** Focus order, keyboard paths, roles and labels must not depend on a pack's layout. Visual reordering keeps DOM order.

## Acceptance re-skins (rough, per finished screen)

- **Origin Navy:** tokens only, no part CSS. A nod to upstream's navy look. If the screen can't be recoloured without editing it, a token is missing.
- **Banana Cocoa:** the chat screen as a messenger layout (yellow bubbles on blue, own messages on the right). Part CSS may rearrange layout. If the parts can't be rearranged, the structure is too rigid.

These are rough probes of the contract, not finished packs. Put them under `<area>/themes/` as an override stylesheet loaded by `?theme=origin-navy|banana-cocoa`, plus stills at 360 and 1280. Record every token or part name the screen had to gain.

Out of scope for now: finished packs, fonts, images, pack loading and the theme picker. Other acceptance packs (Office Sheet, Terran Eclipse, Scratch White) are tested later by Lane A.

## Contract refinements (2026-10-27)

- **Role tokens are the contract** ([DD-148](DECISIONS.md)). Packs set role tokens, e.g. `--message-gap`, `--header-height`, `--composer-field-height`, `--sheet-padding-x`; the full list is in each area's THEME_AUDIT.md. The ranked ladder (`--space-N`, `--size-N`, `--offset-N`) is internal and may be renumbered.
- **One meaning per name** ([DD-145](DECISIONS.md)). A shared token name means the same thing with the same Deep Nexus default on every screen. Shared names live in `theme/nexus-tokens.css`; a screen-only value gets a screen-prefixed name.
- **Channel tokens for tints** ([DD-146](DECISIONS.md)). Tinted colours use `rgb(var(--nexus-<name>-rgb) / <alpha>)`, so a pack sets each colour once. Solids derive from their channel too, e.g. `--nexus-accent: rgb(var(--nexus-accent-rgb))` ([DD-158](DECISIONS.md)).
- **One layout and input attribute set** ([DD-147](DECISIONS.md)): `html[data-layout=wide|mid|phone]` and `html[data-input=touch|hover]`. Packs may set tokens under these root attributes, as well as `:root` ([DD-159](DECISIONS.md)).
- **Protected surfaces are enforced at install** ([DD-149](DECISIONS.md)). A pack selector that can match inside `[data-part-critical]` is rejected, descendants included. Protected children have their own part names. Any sheet with a danger button, or one that drops data, is protected by default. Reach is judged by ancestry: a rule whose subject may be a protected element, one of its ancestors or one of its children is checked against a declaration allowlist after escapes are normalised. Layout-breaking padding, margin, animation and flex changes fail ([DD-155](DECISIONS.md)).
- **The install rule fails closed** ([DD-242](DECISIONS.md), [DD-243](DECISIONS.md); validator `chat/checks/th/packlint.mjs` with `chat/checks/th/failclosed.mjs`, regression suite `theme/checks/run.mjs`). A pack passes only if all of these hold, judged over the worst case of every declaration it makes (`:root`, a root attribute, any `@media` block, any `var()` chain):
  1. **Role tokens only.** A pack may set a custom property only if its registry lists it as pack-settable: the shared colour and role names (`--nexus-*`, `--color-*`, the shared decoration hooks), the area's role tokens, and tokens the area deliberately bounds with a floor and a ceiling. Anything else is rejected with "not a pack-settable token": the internal ladders (`--space-N`, `--size-N`, `--studio-sz-*`, `--studio-sp-*`, `--studio-font-*`, `--home-space-*`, ...), `--risu-animation-speed`, and a pack's own private variables (`--banana-yellow`, `--bc-*`, `--msg-*`). **One exception (DD-258):** a pack may keep private helper variables under the prefix `--pack-` (rename `--bc-*`, `--banana-*`, `--msg-*` to `--pack-bc-*` and so on). The validator inlines them before judging: every `var(--pack-x)` becomes each value the variable has anywhere in the pack (`:root`, a root attribute, an `@media` block, a chain of other private variables) and the stylesheet is judged once per combination, so a private variable cannot carry a value past a floor, a ceiling, a colour rule, a contrast pair or an allowlist.
  2. **Colours resolve.** Every value of a colour or channel token must resolve to a concrete sRGB colour (hex, `rgb()`, `hsl()`, a named colour). `color-mix()`, `oklch()`, `lab()`, `hwb()`, `light-dark()`, relative colours, `currentcolor`, `inherit`, unknown functions and an unresolved `var()` are rejected, whatever the token. A fully transparent value is rejected too (the two canvas blooms and an area's listed decorative tokens may be switched off). A channel is three numbers from 0 to 255.
  3. **Protected surfaces stay opaque and readable.** The sheet and toast colours (and each area's listed surface tokens) must resolve to alpha 1. Text, secondary and muted text, danger, warning, on-accent, diff and ring tokens that critical parts read must keep 4.5:1 (3:1 for non-text) against the sheet or toast they are drawn on. A background on a selector that names no part (`[data-kind="restore"]`, `[data-state="failed"]`) is rejected, because it can match a protected element itself.
  4. **Key controls are in the reach tier** (DD-243): navigation, Tasks, Stop, the composer with its field and Send, Apply, Undo and Redo, and the failed-save chip with its Retry. A pack may recolour, reborder and respace them; it may not hide, fade, move or re-lay them out. A control that paints its own fill is judged as a pair (text on fill, 4.5:1).
  5. **No pack rule changes an outline.** `outline`, `outline-*` are rejected on every part; a rule in a focus state may not set `box-shadow` or a border to none or fully transparent. The ring tokens keep a floor (`--nexus-focus-ring-width` 1 px).
  6. **Sizes are bounded and must add up** (DD-260, DD-256). Size role tokens that had no limit (`--header-height`, `--message-gap`, the sidebar and sheet widths, avatar and touch sizes, font sizes, the Studio tree, tab and row heights) have ceilings; padding on an ordinary (safe) part is capped at 64 px or 20%, like the reach tier. The horizontal padding and border a pack gives the parts of one ancestor chain (for example `studio-shell > studio-main > studio-body > studio-form-host`) are summed in the worst case and may not exceed 120 px of a 360 px phone. For each protected sheet or dialog the lint estimates the height at 360 px wide from the geometry tokens it reads, each at the largest value the pack gives it. A sheet that does not scroll must fit 640 px (the warning and progress pattern's sheets). The sheets of chat, Settings, Studio and Home all cap their height and scroll inside, so for them the lint judges the part that does not scroll: it plus one action row must fit under the cap, or the actions have no room. The estimates are calibrated against rendered pages at 360x640 touch in Korean (`theme/checks/calibration.txt`): each area's reference model is an upper bound of every rendered protected sheet, 1.03 to 1.25 times the tallest.
  7. **A selector that names no part cannot resize** (DD-265). `[data-kind=...]` and `[data-state=...]` can match a protected element itself, so such a selector may not set `padding`, a border or border width, `font-size`, `width`, `min-width` or `max-width` (it already may not set a background). The root of a protected sheet (`chat-sheet`, `studio-sheet-root`, `home-dialog`) keeps the page's width: a pack may leave it `auto`, `none` or `100%`.
  Other safe parts keep the freedom DD-155 gave them: a pack may still hide a decorative banner or a problems list.
- **No size floor** ([DD-151](DECISIONS.md)). Packs may set touch-target and text-size tokens below 44 dp. Deep Nexus and the acceptance packs keep 44/48 dp.
- **Extended state and parts** ([DD-153](DECISIONS.md)). Streaming, selected, hidden-from-AI, bookmarked, current and unread states are `data-*`. Buttons, fields, composer innards, header title, list-row innards and sheet header/handle have parts. Selection, scrollbar, caret and icon size/stroke have tokens.
- **Selection colour:** Deep Nexus uses an accent-tint text selection, the one deliberate change to the default look ([DD-156](DECISIONS.md)).
- **Origin Navy** uses upstream's default scheme colours, adjusted for AA ([DD-150](DECISIONS.md), Settings DS-076). Banana Cocoa puts own-message actions beside the bubble on hover input and above it on touch ([DD-152](DECISIONS.md)).
