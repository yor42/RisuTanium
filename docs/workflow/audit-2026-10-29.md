# Workflow token audit — 2026-10-29

Scope: token usage of the campaign lanes since the [2026-10-08 audit](audit-2026-10-08.md), measured from Claude Code session transcripts. Window: 2026-10-08T00:00+09:00 to the snapshot end, 2026-10-28T23:45Z (= 2026-10-29 08:45 KST). Lanes: A, A-pre (the Main Campaign sessions before the lane rename), F and G, with lanes B to E shown for context. Authorized by the maintainer on 2026-10-29. This audit measures usage; it does not change policy and claims no savings.

All figures come from the corrected measurement v2 (`wf-audit-v2` in local scratch: `lane_totals.csv`, `sessions.csv`, `agents.csv`, `result.md`) and the independent verification of v1 (`wf-audit-verify`). Both are local and not in the repository. Reproducibility therefore rests on those scratch files, not on this document.

"Tokens" below means the unweighted sum input + cache_creation + output, excluding cache reads. The three classes are billed differently and cache reads are not free, so this sum is a size measure, never a cost or quota proxy.

## Method

- Input: usage fields, timestamps, model tier, ids, session titles, working directories and agent dispatch labels. No message content, tool input or output, or prompt was read.
- Dedupe: one assistant line per content block is written with the same message id; the last line per id per file is kept (671,548 lines to 136,997 messages). Ids repeated across resumed or forked files (640) are kept once, in the earliest file; the choice of file changes totals by under 0.005% (verification). 13 synthetic messages are skipped. 113,883 messages fall in the window.
- Cache-read share = cache_read / (input + cache_creation + cache_read). Peak context = largest per-message input + cache_creation + cache_read in a transcript (window occupancy including the cached prefix, not fresh tokens). Wall time runs from first to last timestamp and includes waiting.
- A subagent belongs to the lane of the session directory that holds it, except 02da88e4 (below). Role and label come from each agent's dispatch metadata.
- Lane A's subagent total is dispatcher spend: lane A also ran phone device runs and records fold-ins for other lanes' stages.

## Reject-loop findings (inferred from dispatch labels; verdicts unobserved)

REJECT or approve verdicts are never visible in usage data. Everything in this section infers rounds from label text ("Gate 1 round 4", "after 3 rejects", "Implement ... v6"). The loop-definition numerator counts every Gate 1 agent at round 2 or later (including the likely approving round), advisors, plan-revision investigators and remediation agents; it is not a count of rejected reviews. Orchestrator-side plan revisions in the main session are not agents and are unmeasured. A missing round number is read as round 1, so maximum rounds are lower bounds.

## Caveats

- Live transcripts: the lane A, F and G orchestrators were still running. The extract is a fixed snapshot; a fresh scan moved lane F by 2,005 tokens (one boundary message) and all totals by about 0.001%. Messages written after 2026-10-28T23:45Z are not counted.
- Labels are heuristics. Ticket, activity and round assignments are inferred from dispatch labels; "~" buckets are keyword or stage guesses. Unclassified agents: A 309 of 530, A-pre 604 of 937, F 34 of 248, G 25 of 182, B 99 of 473. Haiku-editor agents are always classed as remediation, regardless of label (none occur in the CHORE-396, 397 or 375 groups).
- Wall time includes waiting and resumed time, so it is not working time.
- Lane F reviewer share is 44.0% here against about 43.6% in the verification; the 0.4-point gap is unexplained and not material to the reading.
- The 02da88e4 main file's first line is 2026-10-26T23:39Z although 303 of its subagents predate it (from 2026-10-23T06:43Z). Why (retention, fork or resume artifact) and under which orchestrator title those agents ran is not established. Lane A's b5cab228 has the same oddity (agents from 2026-10-23T06:06Z, main from 2026-10-24T00:11Z), but its labels are lane A work, so lane totals are unaffected.
- Transcripts are read as present on disk; rotation or deletion cannot be excluded. Files modified before 2026-10-07 were not read. Messages before the window are dropped message by message, so an agent that straddled the window start is partly counted.
- Per-lane totals are by dispatching session directory, not by whose work it was. The session `2d6ca559` is the likely match for the brief's `local_21a657d7...` id (low-medium); it does not affect totals.
- `session_totals.csv` still lists 02da88e4 under lane F; use `lane_totals.csv`, `sessions.csv` and `agents.csv`.
- Unweighted tokens are not comparable across lanes with different output or cache_creation mixes as if they were cost ratios.

## v1 corrections

The independent verification of v1 found one material error and several wording faults. This audit carries the corrections.

1. Lane mapping: v1 put all of session 02da88e4 in lane F. Subagents dispatched before 2026-10-27T03:00Z (303 agents, 58,279,293 subagent tokens) and the main-file messages before the cut belong to lane B. Lane F fell from 22,312 turns and 112,293,454 tokens to 11,499 and 53,705,080; lane B rose from 7,545 turns and 31,347,598 tokens to 18,358 and 89,935,972. Subagent share of F fell from 93.2% to 86.4% and cache-read share rose from 96.7% to 97.1%.
2. v1's remedy "if 088b9249 is lane F's, move 11.49M from B to F" pointed the wrong way and is withdrawn; 088b9249 is lane B.
3. Context: v1's lane F showed 205 of 551 agents at or above 150k with a 512,446 maximum; that maximum was a lane B coder. Corrected lane F: 87 of 248, maximum 320,787.
4. Gate share: v1's 38% for F was a gate-labelled share on a lane that was over half lane B work. Corrected: 44.0% by reviewer type, 42.5% by gate label.
5. CHORE-375: a classifier pattern matched "fixture" and counted a test helper (132,938 tokens) as remediation. Loop share corrected from 27.6% to 25.3%.
6. CHORE-396 is now an upper bound (65.0%) with 55.6% and 46.4% alternatives. CHORE-397 states one denominator per figure (v1 mixed 11 agents with a 13-agent table). The S4C note about the lane A translator and the missing r5 reviewer was added.
7. Wording: the cache-read range sentence was self-contradictory and is replaced by the per-day and per-lane extremes above; "excl. cache read" is now called an unweighted count, not a cost proxy; lane A's spend is called dispatcher spend; main-session peaks of about 367k apply to A, F and G only (A-pre mains reach 447k); thinking tokens are no longer assumed to be a subset of output.
