### Replay matrix (strict index; real outcomes of `planReplay`, `historyModel.ts` 2002-2046)
On a failed forward plan `planReplay` runs the opposite plan as a witness (tags off); a passing witness returns `already` (no write; the step still moves stacks); otherwise the kind is `changed` (`idTaken` is only the FORWARD intent kind, `ownerHistory.svelte.ts` 1042). Outcomes are from Gate 1's executed probes (same planner code); the tests here are DESIGNED, NOT DEMONSTRATED.
| Situation | Undo / redo / revert / restore |
|---|---|
| Linear history | `ok` |
| Out-of-band edit shifted the member after "add X" | Undo `changed`; nothing written |
| X removed out of band after "add X" | Undo `already` (no write; step to undone); Redo re-adds X if the recorded index is in range, else `changed` |
| Undo of remove of B, B re-added elsewhere, values or index differ | `changed`; no duplicate |
| Undo of remove of B, an identical row at the recorded index | `already`; no write |
| Set-undo/redo when live equals the step's `before` (resp. `after`) | `already` |
| Set-undo when live differs from both | `changed` |
| Insert replay above the current length | `changed` (no clamp) |
| Arrays of different lengths / non-array / holes | reader null: every `members` op `precondition`; nothing written |
| chaId occurs twice | Add refused by the builder; remove/set builders refuse; a replayed step whose recorded row and index match applies; otherwise `changed`, or `already` when an equal row sits at the recorded index |
| Member's character gone / archived | replay never reads or restores it |
| Group gone / archived / duplicate-id / not selected | adapter refuses (`gone`, `duplicate-id`, `not-selected`) before any write |
Restore lines and revert run the same planner per step; a refusal refuses that line. Session history is memory-only (like `preset`): no store retention, GC, claim or record parser applies; no older build can refuse a record. The in-memory record still obeys `MAX_DONE/UNDONE`, Rule K (`ownerHistory.svelte.ts` 1037) and the visit journal. Members never carry `deletedId` (no History deleted item for them, deliberate).
