# device-guard

`adbg.mjs` is the adb accident guard for agent-driven device runs. Every device brief requires all adb calls to go through it; a direct `adb.exe` call is a rule breach, and the independent check lists any call made outside the guard. The device kit (`Agents/Tools/device` and `Agents/Tools/chatshell-cdp/device`) runs every adb call through this guard with `--kit`, which refuses any serial other than the two spare Note 9s; the only guard callers without `--kit` are agents' direct calls and tbdriver's `tbg.ps1`.

It is an allowlist: plain calls run only if they match the short list at the top of the file (a few `shell` commands in printable ASCII with no control characters or shell metacharacters, `ps -A | grep <literal>` as the only pipe, `logcat --pid`, `exec-out screencap -p --out <png>`, forward/reverse on the run's own `--own-ports`, `get-state` and `start-server` (no further arguments), `install`, `push` to an exact `/sdcard/Download/<name>` whose name does not start with a dot). `ls`, `sha256sum`, `rm -f`, `pull` and the output of `screenrecord` take one file directly in `/sdcard/Download` or `/data/local/tmp`; `pull` needs a name with an extension and writes only a new file, by an absolute path directly in the folder that holds `--log`, with a plain name (`[A-Za-z0-9._-]`, an extension, no device names); it never overwrites; `screenrecord` needs `--time-limit` (1 to 30 s); `logcat --pid` may add `-s <Tag>`. `rm` passes only as one command string `shell 'rm -f <path>'`, with `<path>` one file directly in `/sdcard/Download` or `/data/local/tmp` whose name is `[A-Za-z0-9._-]` and does not start with a dot (the one other accepted form is the r14 export path given as separate arguments, on the playground serials only); bare `rm <path>`, `rm -r`, `rm -rf`, two paths, globs, other or nested folders and dot-names exit 97 on full-access serials, and restricted serials refuse every `rm` with exit 95. `sha256sum` also accepts the own package's installed `/data/app/.../base.apk` (as `pm path` prints it) for the install read-back. `exec-out screencap -p --out <png>` must return a PNG; with `--state` it is noted for `locate-shot`. `pm clear`, `am force-stop`/`kill` and `am start -n` need `--own-package` and accept only that app; `am start` refuses `-d`/`--data` and any `scheme://` URI (apart from the r15 item forms); on `emulator-5580` (r20, CHORE-848) every `am start` must be exactly `am start [-W] -n io.github.yor42.risutanium/<activity>` (`<activity>` is `[A-Za-z0-9._]+`, blanks collapse; the package is the constant, not `--own-package`, which must still name the app id), so no implicit, action, data, extras, other-package or `tel:`/`sms:`/`mailto:`/`content:`/`file:` start passes, with exit 97 and nothing sent; the restricted `am-start` scope class is unchanged (it opens `am start [-W] -n <own package>/<activity>` for whichever package the scope file's call names with `--own-package`, so a scope for a dialer or browser package stays the maintainer's decision); r17 also narrows every `am` line to a closed character set (see the r17 item below). Everything else is refused (exit 97). Every call writes an intent line before it runs and an exit line after, in the run's `adb-commands.log`; adb calls time out (10 min, 2 h for `push`, 60 s for screencap and pick) and log `exit=timeout`. The two Note 9 serials are the exception: they run the Note 9 profile (r3, below), a denylist of danger zones (exit 89) instead of this allowlist.

- `pick --name <exact>`: the picker helper of MC-1438. One device-side command dumps, greps for the exact name, prints only the bounds and deletes the dump by its exact name; the output is `match bounds=...` or `no-match`. The first no-match writes `PICK-LOCK` to the log and every later pick in that run is refused (exit 98). A transport error exits 4 without locking, at most twice.
- `pick --id com.android.documentsui:id/<name>` (MC-2303, MC-2306): the same helper keyed on an exact resource id instead of a text, so it works whatever the UI language is (for the system file picker's multi-select confirm button, `com.android.documentsui:id/action_menu_select`). Playground serials only (`emulator-5580` exits 97, restricted serials 95). The id must match `^com\.android\.documentsui:id/[a-z][a-z0-9_]{0,79}$` exactly, and only `--serial`, `--log`, `--state`, `--id`, `--own-package` and `--own-ports` are accepted, each once with a value, with no `--` section and not together with `--name`; any breach exits 2 with no adb call. A system file picker must be in front first (`com.android.documentsui` or `com.google.android.documentsui`, `oom_score_adj` 0), otherwise exit 93 with no dump and no `PICK-LOCK`; that refusal counts toward the two-error cap that both forms share, so two of them make the next `pick` of either form exit 98. A no-match or a second hit locks both forms exactly as for `--name`. The match is on ` resource-id="<id>"` including the closing quote, so a longer or shorter id never matches. The `tap` that follows is the ordinary `tap` and consumes the locate.
- `pick --id android:id/button1` (r18, 2026-11-18, CHORE-227 D1 save rows): the one extra id `pick --id` accepts, the Save button of the Samsung save picker (`CREATE_DOCUMENT`); `KEYCODE_ENTER` does not press it while the filename field is unfocused. Exact match only: `android:id/button2`, `android:id/button10`, `android:id/title` and every other `android:id/*` exit 2 with no adb call. Everything else is as for the `com.android.documentsui` ids: playground serials only (95, 97), a system file picker in front (exit 93), `PICK-LOCK` and the two-error cap. Save-screen proof, fail-closed: the same single dump must also hold a node with `resource-id="android:id/title"` and `class="android.widget.EditText"` (the filename field). On a replace or overwrite confirmation dialog `button1` means "replace" and no such field exists, so without it the guard reports no bounds, taps nothing, still removes the dump, and exits 4 with `button1 refused: no save-screen filename field in the dump`. That is a pick error (counts toward the two-error cap, sets no lock), not a no-match. The log line reads `pick --id android:id/button1 (save confirm, r18)`.
- `offset`, `locate-css`: record where an element is, in device pixels, from a read-only CDP read; the element must be inside the viewport and on top at its centre. `locate-css` needs `--own-ports` containing `--port` and `--url-contains`, which exactly one page target must match. Page text is never printed.
- `file-chooser --serial <s> --log <log> --state <state> --own-package io.github.yor42.risutanium --own-ports <p,...> --port <own port> --selector <css> [--text <exact label>] --file <device path> [--timeout-s <1-30, default 10>]` (rNN, number assigned by lane A; maintainer MC-2724 to MC-2726): hands one already-pushed synthetic file to the app's own `<input type=file>` over CDP, so no system picker is ever operated. Only the two Note 9 serials run it (restricted, unknown and near-miss serials exit 95 before any adb call, `emulator-5580` exits 97); it is not a plain adb call (`-- file-chooser ...` stays 97, `--kit` is exit 2). Options only, no `--` section, each key once with a value. `--file` is exactly `/sdcard/Download/<name>` or `/sdcard/Android/data/io.github.yor42.risutanium/files/<name>`, `<name>` 1 to 100 chars of `[A-Za-z0-9._-]` with no leading dot (no traversal, no other folder); `--state` must hold an `offset` record (integer `x` and `y`, 0 to 4000), else exit 2. Checks before any CDP method: the cap (exit 98 after two counted failures in that `--state`); the device file (`[ -f p ] && [ ! -h p ] && stat -c %s p`: a regular, non-symlink file of size above 0, else exit 4); exactly one `adb forward --list` line for this serial and `tcp:<port>` to `localabstract:webview_devtools_remote_<pid>` (none: 5, a second line or another remote: 96; the raw list is never printed or logged); `pidof` lists that pid (else 96); its `oom_score_adj` is 0 (else 93); `/json/version` reports `Android-Package` = our package and `/json` lists exactly one page whose `webSocketDebuggerUrl` is `ws://127.0.0.1|localhost:<port>/devtools/page/<id>` (redirects refused; else 96, or 5 for a transport failure or a page count other than 1). Then one WebSocket sends only eight CDP methods (at most 9 sends, each logged as `cdp: <method>`): `Runtime.evaluate` (the `locate-css` element probe: one match, fully in view, on top, else exit 6), `Page.enable`, `Page.setInterceptFileChooserDialog {enabled:true}`, then, only when both replies were results, the single `input tap` at the probed centre (offset + rect * devicePixelRatio), `Page.fileChooserOpened` (events are buffered, so one that arrives while the tap blocks the guard is not lost), `DOM.setFileInputFiles` with exactly the one validated path and the event's node, `DOM.resolveNode`, `Runtime.callFunctionOn` (the page reads up to 64 KiB of the file through its own `File` and reports count, name, size and bytes read), `Runtime.releaseObject`, interception off, `Page.disable`. Every reply must carry a `result` and no `error`. Exit 0 prints `file-chooser ok name=<n> size=<n> head=<n> mode=<m>` and needs one file with the expected name and the device's size, `min(65536, size)` bytes read, and both cleanup replies acknowledged. Exit 7 covers everything from `Page.enable` on (interception refused, tap failed, chooser not opened or malformed, file not set, content not read or mismatched, interception off not acknowledged); nothing between `Page.enable` and the end of the cleanup calls `die()` or `process.exit`, so a thrown error there is a 7 and the cleanup and the cap still run. If the chooser does not open and a system picker is in front, the reason says to press Back once via the guard and stop; the verb itself never sends a key and never taps anything but the probed control. Counted toward the two-failure cap (`fileChooserErrors` in `--state`): 4, 5, 6, 7, 93 and 96; 2, 95, 97 and 98 are not. Residuals, named: a killed process skips the cleanup (Chromium scopes the interception to the session); an own port is agent-exclusive but not locked between `forward --list` and the HTTP read; the `offset` record carries no serial; a fresh `--state` resets the cap; "the picker is never shown" holds only for controls that open an `<input type=file>` in a WebView that honours interception. Tests: `test/file-chooser.test.ps1`.
- `locate-shot --png --label --box l,t,r,b`: records a box the agent found by pixel analysis in the newest screencap taken with the same `--state`, at most 10 s old, for surfaces where UI dumps are banned (the notification shade). One locate per screencap; a failed capture or a tap clears it, so the next control needs a fresh capture. Always screencap with `--state` when using it.
- `proc-tasks --pid <n>`: per-thread `tid comm utime stime` of one process, read only after the same device command confirms its cmdline is `--own-package` or a WebView sandboxed renderer (it cannot tell our renderer from another app's; the brief picks the pid). Nothing else under /proc/<pid>/task is printed.
- `tap`: taps only the newest locate record, at most `--max-age` seconds old (1 to 10, default 5), once per record (exit 99 otherwise).
- `tap-home --delay-ms <0-500>` (2026-11-11, lane A, CHORE-719): the only chained verb. One call taps the newest locate exactly as `tap` does (full-access serials only, the locate must be fresh and unused and is consumed, same exit codes), waits the fixed delay, then sends `input keyevent KEYCODE_HOME`. No other keycode can be chained. A delay that is not an integer from 0 to 500 exits 2; a failed tap sends no HOME; a restricted serial gets exit 95 even with a `tap` scope. The log holds both steps and a `tap-home timing` line with epoch-ms start/end of each and the tap-to-HOME gap. It grants no typing chain, so `input text` afterwards is refused (exit 99).
- `swipe --duration-ms <50-5000> (--dx <px> --dy <px> | --to-x <px> --to-y <px>)` and `hold --duration-ms <100-5000>` (2026-11-12, MC-1539): gestures from the centre of the newest fresh, unused, same-serial locate (the `tap` rules; the locate is consumed). `swipe` ends at start plus `--dx/--dy` (each at most the screen size the locate recorded, else 3000) or at `--to-x/--to-y` inside the screen; it sends exactly `input swipe x1 y1 x2 y2 ms`. `hold` sends `input swipe x y x y ms` (zero distance). Both need `--own-package` and first check read-only that our own package is in front (`pidof <package>`, then `/proc/<pid>/oom_score_adj` reads 0); another package in front exits 93 and sends nothing (on the two playground serials only, `com.android.documentsui` or `com.google.android.documentsui` in front also passes, see below). Bad arguments exit 2 with no adb call; neither verb grants typing, so `input text` afterwards is refused (exit 99); restricted serials always get exit 95, even with a tap scope.
- Hard stop after a failed locate (2026-11-12, MC-1539): when `pick`, `locate-css` or `locate-shot` exits non-zero for a serial, the guard records an input lock for it (in `--state` and as an `INPUT-LOCK` line in the log). While locked, every input-sending command (`tap`, `tap-home`, `swipe`, `hold`, `input keyevent` of any key including BACK, HOME, DPAD and PAGE_DOWN, `input text`, the edit keys) exits 92 and logs `refused: input after failed locate`, with no adb call. Only a later successful locate for that serial clears it; screencap, locate and read commands stay allowed; another serial is unaffected. This closes the breach of the 2026-11-12 cloud UI run (guard log line 409): a failed locate followed by KEYCODE_BACK before any fresh locate. A restricted-serial refusal of the verb itself (exit 95) is not a failed locate.
- Typing chain (2026-11-11, lane A): `input text` and the edit/submit keys (TAB, ENTER, DEL, FORWARD_DEL, by name or code) need `--state` and run only when the previous action line in the log is the successful `tap` that granted typing, or a successful typing call of that chain, within 30 s of the tap. One `input text` per tap; any other guarded call in between (a refusal included), a failed tap or a failed typing call ends the chain (exit 99). Other `input keyevent` keys are navigation only: HOME, BACK, POWER, MENU, ESCAPE, APP_SWITCH, WAKEUP, SLEEP, the four DPAD arrows, PAGE_UP/DOWN, MOVE_HOME/END (by name or code); DPAD_CENTER, SPACE, letters, digits and flags such as `--longpress` are refused (exit 97). Any guarded call between the tap and the text (a screencap included) ends the chain: tap, then type at once.

## Playground mode (2026-11-13, MC-1666)

The two spare Note 9s, `29f3cde9193f7ece` and `2ac80128013f7ece`, hold only synthetic data. Those two serials, and no other, run in playground mode. Membership is the exact `--serial` string compared with the constant `PLAYGROUND_SERIALS` in `adbg.mjs` (no prefix, case or substring match); no flag, env var, state file, scope file or log content can add a serial or switch the mode on, and `emulator-5580` stays an ordinary full-access serial. The guard stays mandatory as the audit log: every call is logged, a playground-allowed call also gets a `PLAYGROUND serial=<s> allow=<r11|extended> adb [...]` line (`extended` marks what only playground opens), every adb call is sent `-s <--serial>` (a `-s` or `-P` inside the adb arguments is refused, exit 97), and everything r11 allows still works. Every other serial behaves exactly as before (restricted serials exit 95, `emulator-5580` as in r11).

## Note 9 profile (r3, 2026-11-19, lane B)

On a playground serial (the two Note 9s) plain `adb` calls are judged by a denylist of danger zones instead of the allowlist above; tests are in `test/note9-profile.test.ps1`. The Tab, every unknown serial (restricted, exit 95) and `emulator-5580` (r11 allowlist) are unchanged. Exit 89 is a danger-zone refusal (the call is not sent, the log names the zone and the serial); exit 97 is a shape refusal. r14, r15 and r17 forms still work and are no longer the limit on the Note 9s.

- Full control. Verbs: `shell`, `exec-out`, `push`, `pull`, `install`, `install-multiple`, `uninstall`, `logcat`, `forward`, `reverse`, `get-state`, `start-server`, `wait-for-device` and `reboot` with no argument. Any other verb, a leading global option (`-s`, `-t`, `-d`, `-e`, `-H`, `-P`, `-L`, `--one-device`) and a non-printable-ASCII argument exit 97. `shell` and `exec-out` take any command string (pipes, `;`, `&&`, redirects, `$(...)`, quotes and globs in arguments) but never a bare `shell` or a shell option; `exec-out screencap -p --out <png>` keeps its PNG check. `input` needs no locate, typing grant or input lock. `pm clear` and `pm uninstall` of `io.github.yor42.risutanium` need no `--own-package`. `push` takes any local source to any absolute device path (`--sync` allowed); `pull` takes `[-a] <absolute device path> <a new path directly in the run folder>` (never the log or state file, no device names; a directory can be pulled); `install` takes one local `.apk`, `install-multiple` one or more, with the flags `-r -d -t -g` only; `uninstall [-k] <package>`; `logcat` takes any arguments (a streaming call ends at the 10 minute adb timeout, so use `run_in_background`); `forward` takes an own port as before, plus the r21 kit forms named in the network item below. Pushing and running any executable is allowed (its content is not inspected). `adb reboot` with no argument is allowed to recover a hung phone; every reboot target and every shell `reboot` is 89.
- Danger zones, exit 89 (stop that line of work and report it; never retry a variant: another quoting, a variable, a glob, a script or a binary that does the same). The scan reads lower-cased text with `${IFS}` and `$IFS` read as a blank, then quotes and backslashes removed (so `svc$IFS'wifi'$IFS'enable'` is read as `svc wifi enable`), on shell strings, exec-out strings and push and pull paths. r20 scans the text a second time after one percent-decoding pass (`%XX`, both hex cases, no `+`; a malformed `%` stays as written), so `content://c%61ll_log`, `t%65l:` and `%43ontacts` are refused; the raw text is judged first and the decoded text only adds a refusal. Residuals: double encoding (`%2561`) passes, and a harmless name that decodes to a zone word (`a%20call.txt`) is refused. DZ-1 contacts, call log, SMS/MMS, calendar, voicemail, blocked numbers, SIM phonebook (word prefixes `contact`, `call_log`, `voicemail`, `blockednumber`, `calendar`, `telephony`, `phonebook`; words `sms`, `mms`, `icc`, `dialer`, `messaging`). DZ-2 outbound calls and messages (words `call`, `dial`, `phone`, `smsto`, `mmsto`, `mailto`, `sendto`, `emergency`, `isms`, `callto`, `endcall` (so `KEYCODE_ENDCALL` and the bare label `ENDCALL` too), the schemes `tel:`, `sip:` and `sips:` (left boundary, so `gossip:` passes), an intent URI part `scheme=tel|sip|sips|callto`, and the decimal key codes `5`, `6`, `207` and `208` of `input keyevent`, also with a leading `+` or zeros). DZ-3 accounts and sync (prefix `account`, word `signin`, `auto_sync`, `master_sync`, `sync_settings`, `requestsync`; the adb verbs `backup` and `restore`). DZ-4 device admin, lock credentials and anything that cuts adb off (`dpm`, `locksettings`, `device_policy`, `adb_enabled`, `adb_wifi`, `development_settings_enabled`, `svc usb`, `sys.usb.`, `service.adb.`, `set-user-restriction`, `no_debugging_features`, `switch-user`, `stop-user`). DZ-5 wipe, recovery, bootloader, reboot, shutdown (`recovery`, `wipe`, `reboot`, `powerctl`, `shutdown`, `factory`, `master_clear`, `sm format`; the verb `sideload`). DZ-6 `pm` or `cmd package` uninstall, disable, hide, suspend, clear and the like of anything but `io.github.yor42.risutanium`; the whole command must be exactly `pm clear [--user 0] <app>` or `pm uninstall [--user 0] [-k] <app>` (either option order), so a chained command such as `pm clear <app> && am start ...` is 89 on purpose: send `pm clear` and `pm uninstall` as their own call. DZ-7 root, remount, verity, `su`, `magisk`, `setenforce`, `/dev/block`; the verbs `root`, `unroot`, `remount`, `disable-verity`, `enable-verity` and `sync`. DZ-8 network on: `svc wifi|data|bluetooth|nfc enable`, `cmd wifi`, `cmd bluetooth_manager`, `airplane-mode disable`, the radio keys (`wifi_on`, `wifi_saved_state`, `mobile_data*`, `airplane_mode_on`, `bluetooth_on`, `*_scan_always_enabled`, `data_roaming*`) anywhere in the text, so `content insert ... wifi_on` is refused too, proxy, Private DNS, VPN and tether keys and intents, `ifconfig`, `ip link|addr|route|rule`, `iptables`, `ndc`, `wpa_cli`, `rndis`, `android.settings.(wifi|wireless|airplane|network|internet|bluetooth|nfc|...)`, `adb.tcp.port` (`setprop persist.adb.tcp.port 5555` turns on adb over TCP), the `android.bluetooth.adapter.action` family (`REQUEST_ENABLE`) and a `com.android.settings/` component whose class names `wifi`, `network`, `account`, `security` or `reset` (`am start -n com.android.settings/.wifi.WifiSettings`); `am start -a android.settings.SETTINGS` and `-n io.github.yor42.risutanium/.MainActivity` still pass; the verbs `tcpip` and `usb`. The disable direction stays allowed (`svc wifi disable`), and so do these exact whole commands: `settings get <global|secure|system> <radio or proxy key>` and `settings put global http_proxy :0`. Read radio keys and `adb_enabled` one per call, or use `net-status`: a combined read such as `settings get global wifi_on && settings get global airplane_mode_on` is 89, and `settings get global adb_enabled` is 89 (DZ-4). DZ-9 the words `risuai`, `risurealm`, `realm`, `discord`, `discordapp`. DZ-13 `monkey` as a command word (`monkey 100`, `monkey -p <pkg> ...`, `/system/bin/monkey`): it injects random taps that can reach calls, Settings and accounts, so it is 89 (file names that only contain the word, such as `monkey.txt`, pass). DZ-10 other devices and host-wide verbs: `connect`, `disconnect`, `pair`, `reconnect`, `kill-server`, `emu` and a `reverse` host end that names a reserved port (below). DZ-11 network, location and identity dumps: `dumpsys` and `cmd` must name a service first (`[a-z][a-z0-9_.]*`) or be exactly `-l` (and `dumpsys -l | grep x` passes). The words with prefix `bugreport`, `dumpstate`, `incident` (so `bugreportz`, `dumpstatez`, `incidentd`), `/misc/wifi`, `wpa_supplicant` and the adb verb `bugreport` are 89. Everything else `dumpsys` and `cmd` can name passes: `meminfo`, `gfxinfo`, `window`, `activity` (and its sub-arguments), `batterystats`, `cpuinfo`, `webviewupdate`, `package`, `settings`, `accessibility`, `usagestats`, `cmd statusbar` and the state-changing arguments such as `battery set` and `gfxinfo <app> reset`. Use `net-status` for Wi-Fi state. DZ-12 host signing secrets as push sources: a source (every source of a multi-source push, and any file anywhere inside a directory source, walked up to 10000 entries, links not descended) named `key.txt`, `keystore.properties`, `adbkey`, or ending `.jks`, `.keystore`, `.p12` is 89 (`adbkey.pub` passes); a directory with more than 10000 entries, an unreadable source and a source that is itself a link are 97 (push it in parts, or push the link's target path); a source whose own name holds `:` (an NTFS stream suffix such as `key.txt::$DATA`) or `~<digit>` (an 8.3 short name) is 97 (spell the long name). Danger words also appear in harmless names: name fixtures without `contact`, `call`, `phone`, `sms`, `account`, `realm`, `recovery`, `wifi` or `dumpsys` (`ls /sdcard/Download/c128-phonebook-test.json` is 89).
- `file-chooser` (r22): a guard verb of its own on the two Note 9 serials only; it feeds the app's own file chooser one pushed synthetic file over CDP instead of operating the system picker (see the verbs list at the top). Tests: `test/file-chooser.test.ps1`.
- Shape refusals, exit 97: a command NAME built by a glob or brace (`/system/bin/rebo?t`, `sv[c] wifi enable`) cannot be scanned; spell the name out once (globs and brace groups in arguments, such as `ls /sdcard/Download/*.png` or `for f in /sdcard/Download/*.png; do ...; done`, pass; quoted regexes in `grep -E "..."` pass; `echo $((3*4))` is refused because the arithmetic text reads as a command name). Also 97: a verb outside the set, a leading global option, a bare or optioned `shell`, a push with a flag other than `--sync` or a relative destination, a pull whose local path is not a new name directly in the run folder, `install` of anything but a local `.apk`, `reverse --remove-all`, any other `forward` or `reverse` shape than the ones named in the network item below, and `get-state` or `start-server` with an argument.
- Network is `adb reverse` to the run's own host ports, and nothing else. Wi-Fi, mobile data and Bluetooth stay refused (DZ-8). `reverse` passes as `tcp:<own> tcp:<own>`, `--remove tcp:<own>` or exactly `--list` (record it at the start of a run: `reverse --list` shows every reverse on that device); r21 adds the three exact forms the device kit sends, on the two Note 9 serials only: `forward --list`, `forward --no-rebind tcp:<own> localabstract:webview_devtools_remote_<1 to 7 digits>` and `reverse --no-rebind tcp:<own> tcp:<own>` (any other shape, such as another remote, a non-own port, a leading zero, an extra word or `--no-rebind` in another position, is 97; emulator-5580 gets 97 and restricted serials 95 for all three; the forward host end has no reserved-port check, as with the plain forward, and the reverse host end is checked as below); a host end that is the host adb server (5037, the value of `ANDROID_ADB_SERVER_PORT` with surrounding blanks trimmed, or the port of `ADB_SERVER_SOCKET`) or an emulator port (5554-5585) is 89, because a program on the phone could drive every other attached device through it; those two environment variables only narrow what a reverse may reach, they never select a profile. ## Restricted serials

Only three serials get the full allowlist described above, as listed in `FULL_ACCESS_SERIALS` in `adbg.mjs`: `29f3cde9193f7ece` (Note 9 phone 1), `2ac80128013f7ece` (Note 9 phone 2) and `emulator-5580`. Any other `--serial` (a personal device, such as the maintainer's Tab S9 Ultra) runs in restricted mode, fail-closed, whatever the brief says.

- Allowed: `reverse` (with an own port) and `forward` of an own port to `localabstract:webview_devtools_remote_*`, and their `--remove`; `exec-out screencap -p --out <png>` (capture only, of our own app, under the picker gates below; viewing and cropping stay governed by the brief); `shell pidof <own package>`, `shell pm path <own package>`, `shell sha256sum` of the own package's installed `base.apk`, `shell getprop` of a few read-only model/boot keys; the read-only subcommands `locate-css`, `locate-shot` and `offset`. `--own-package` and `--own-ports` still apply.
- Refused with exit 95, naming the restricted serial: `tap`, `pick`, `proc-tasks`, `net-status`, `input` (text, keyevent, swipe), `am`, `pm clear`/install, `svc`, `settings`, `logcat`, `install`, `push`, `pull`, `rm`, `get-state`, `start-server`, and anything else not listed above.
- `--scope-file <path>` is the only way to widen: a JSON file `{"serial": "...", "approvedBy": "maintainer", "date": "YYYY-MM-DD", "allow": ["tap", "input-text", "keyevent", "am-start", "install"]}` written from a maintainer approval. Only the listed classes open, only for that exact serial (a file naming another serial widens nothing; an unreadable or malformed file exits 2). `tap` opens the `tap` subcommand, `input-text` opens `input text`, `keyevent` opens `input keyevent`, `am-start` opens only `am start [-W] -n <own package>/<activity>` (no action, data or extras), `install` opens `install`. The normal allowlist and the typing chain still apply to what opens. Every call that reads the file logs its path and sha256 in `adb-commands.log`; the independent check compares them with the approval.
- Writing a scope file (lane A rule, 2026-11-11): only after lane A relays a maintainer approval that names the serial and the classes; quote that MC ID inside the file (an extra `"mc"` field is fine); keep each file in the run folder, never in this guard folder.
- `reverse` on a restricted serial needs both ports to be own ports (the host end decides which PC service the device reaches).
- Picker gates (r19 Stage B, 2026-11-18; maintainer 2026-11-18 direct, MC IDs pending): on every restricted serial (the Tab and every alias of it, `adb-...` wireless and `model:`/`usb:` qualifier serials included) the guard sends one fixed command of its own that lists the pids of `com.android.documentsui` and `com.google.android.documentsui` and of `io.github.yor42.risutanium` with their `oom_score_adj`. A picker counts as visible when any picker pid has an adj below 300 or one that could not be read; our app counts as in front only at adj exactly 0, and that never overrides a visible picker. The log gets an `intent: picker-probe` line and an `exit=<n>: picker-probe picker=<none|visible|unknown> adj=<numbers> own=<front|not-front|unknown>` line; no raw output is logged.
  - `exec-out screencap -p` needs `--own-package io.github.yor42.risutanium` (any other value exits 95 with no adb call), our app in front and no picker visible, checked before and again after the capture.   - Residuals, covered by the run brief and not by the guard: adj 0 is a proxy for "in front" (a process running a service callback or receiving a broadcast also gets it, so it takes two coincidences); a full-frame capture of our app can still show things drawn over it (status bar, heads-up notifications, the keyboard's clipboard strip, the Edge panel, bubbles, other apps' toasts, a split-screen or pop-up neighbour), so the maintainer keeps do-not-disturb on with pop-ups hidden, no split-screen, and the Edge panel and bubbles closed; the notification shade and the keyguard (our app can keep adj 0 beneath them, and WAKEUP and POWER are navigation keys, so a brief must not wake or power the Tab during a capture step); pickers other than DocumentsUI (the Android 14+ Photo Picker, the intent chooser) are not seen by the input gate, and a brief must stop if one appears; a picker that appears and goes within the gap between the two probes; and CDP input and page scripts inside our own app, which are outside the guard.
- Full-access serials ignore all of this and behave exactly as before.

Limits: it guards against accidents, not against an agent that edits its own state or log files or starts a second log; the brief fixes the log path and the independent check compares the log with the report. It cannot judge what a screenshot shows or whether a destructive target was named. The allowlist is syntactic: it does not pin settings keys, start intents other than URL data, `install`/`push` sources, logcat pids, the serial or which field a tap focused (a tap on a non-text element still grants a chain). CDP input (Input.insertText, Input.dispatchKeyEvent) and page scripts are outside the guard: briefs forbid them and the check looks for them (the eight CDP methods `file-chooser` sends itself are guard-internal and each is logged as a `cdp:` line) (a maintainer-approved run brief may name the CDP actions allowed inside our own app, as for the Tab). Coordinates come from the layout viewport, so an open keyboard or pinch zoom can still move the target; a hung or killed call shows as an intent line with no exit line, which the check reports.
