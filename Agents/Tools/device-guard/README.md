# device-guard

`adbg.mjs` is the adb accident guard for agent-driven device runs. Every device brief requires all adb calls to go through it; a direct `adb.exe` call is a rule breach, and the independent check lists any call made outside the guard. The one exception is a repository tool a brief names explicitly (for example `Agents/Tools/device/sign-install.ps1`), which calls adb itself.

It is an allowlist: plain calls run only if they match the short list at the top of the file (a few `shell` commands in printable ASCII with no control characters or shell metacharacters, `ps -A | grep <literal>` as the only pipe, `logcat --pid`, `exec-out screencap -p --out <png>`, forward/reverse on the run's own `--own-ports`, `install`, `push` to an exact `/sdcard/Download/<name>`). `ls`, `sha256sum`, `rm -f`, `pull` and the output of `screenrecord` take one file directly in `/sdcard/Download` or `/data/local/tmp`; `pull` needs a name with an extension and writes only a new file, by an absolute path directly in the folder that holds `--log`, with a plain name (`[A-Za-z0-9._-]`, an extension, no device names); it never overwrites; `screenrecord` needs `--time-limit` (1 to 30 s); `logcat --pid` may add `-s <Tag>`. `sha256sum` also accepts the own package's installed `/data/app/.../base.apk` (as `pm path` prints it) for the install read-back. `exec-out screencap -p --out <png>` must return a PNG; with `--state` it is noted for `locate-shot`. `pm clear`, `am force-stop`/`kill` and `am start -n` need `--own-package` and accept only that app; `am start` refuses URL data. Everything else is refused (exit 97). Every call writes an intent line before it runs and an exit line after, in the run's `adb-commands.log`; adb calls time out (10 min, 60 s for screencap and pick) and log `exit=timeout`.

- `pick --name <exact>`: the picker helper of MC-1438. One device-side command dumps, greps for the exact name, prints only the bounds and deletes the dump by its exact name; the output is `match bounds=...` or `no-match`. The first no-match writes `PICK-LOCK` to the log and every later pick in that run is refused (exit 98). A transport error exits 4 without locking, at most twice.
- `offset`, `locate-css`: record where an element is, in device pixels, from a read-only CDP read; the element must be inside the viewport and on top at its centre. `locate-css` needs `--own-ports` containing `--port` and `--url-contains`, which exactly one page target must match. Page text is never printed.
- `locate-shot --png --label --box l,t,r,b`: records a box the agent found by pixel analysis in the newest screencap taken with the same `--state`, at most 10 s old, for surfaces where UI dumps are banned (the notification shade). One locate per screencap; a failed capture or a tap clears it, so the next control needs a fresh capture. Always screencap with `--state` when using it.
- `proc-tasks --pid <n>`: per-thread `tid comm utime stime` of one process, read only after the same device command confirms its cmdline is `--own-package` or a WebView sandboxed renderer (it cannot tell our renderer from another app's; the brief picks the pid). Nothing else under /proc/<pid>/task is printed.
- `tap`: taps only the newest locate record, at most `--max-age` seconds old (1 to 10, default 5), once per record (exit 99 otherwise).
- `tap-home --delay-ms <0-500>` (2026-11-11, lane A, CHORE-719): the only chained verb. One call taps the newest locate exactly as `tap` does (full-access serials only, the locate must be fresh and unused and is consumed, same exit codes), waits the fixed delay, then sends `input keyevent KEYCODE_HOME`. No other keycode can be chained. A delay that is not an integer from 0 to 500 exits 2; a failed tap sends no HOME; a restricted serial gets exit 95 even with a `tap` scope. The log holds both steps and a `tap-home timing` line with epoch-ms start/end of each and the tap-to-HOME gap. It grants no typing chain, so `input text` afterwards is refused (exit 99).
- `swipe --duration-ms <50-5000> (--dx <px> --dy <px> | --to-x <px> --to-y <px>)` and `hold --duration-ms <100-5000>` (2026-11-12, MC-1539): gestures from the centre of the newest fresh, unused, same-serial locate (the `tap` rules; the locate is consumed). `swipe` ends at start plus `--dx/--dy` (each at most the screen size the locate recorded, else 3000) or at `--to-x/--to-y` inside the screen; it sends exactly `input swipe x1 y1 x2 y2 ms`. `hold` sends `input swipe x y x y ms` (zero distance). Both need `--own-package` and first check read-only that our own package is in front (`pidof <package>`, then `/proc/<pid>/oom_score_adj` reads 0); another package in front exits 93 and sends nothing. Bad arguments exit 2 with no adb call; neither verb grants typing, so `input text` afterwards is refused (exit 99); restricted serials always get exit 95, even with a tap scope.
- Hard stop after a failed locate (2026-11-12, MC-1539): when `pick`, `locate-css` or `locate-shot` exits non-zero for a serial, the guard records an input lock for it (in `--state` and as an `INPUT-LOCK` line in the log). While locked, every input-sending command (`tap`, `tap-home`, `swipe`, `hold`, `input keyevent` of any key including BACK, HOME, DPAD and PAGE_DOWN, `input text`, the edit keys) exits 92 and logs `refused: input after failed locate`, with no adb call. Only a later successful locate for that serial clears it; screencap, locate and read commands stay allowed; another serial is unaffected. This closes the breach of the 2026-11-12 cloud UI run (guard log line 409): a failed locate followed by KEYCODE_BACK before any fresh locate. A restricted-serial refusal of the verb itself (exit 95) is not a failed locate.
- Typing chain (2026-11-11, lane A): `input text` and the edit/submit keys (TAB, ENTER, DEL, FORWARD_DEL, by name or code) need `--state` and run only when the previous action line in the log is the successful `tap` that granted typing, or a successful typing call of that chain, within 30 s of the tap. One `input text` per tap; any other guarded call in between (a refusal included), a failed tap or a failed typing call ends the chain (exit 99). Other `input keyevent` keys are navigation only: HOME, BACK, POWER, MENU, ESCAPE, APP_SWITCH, WAKEUP, SLEEP, the four DPAD arrows, PAGE_UP/DOWN, MOVE_HOME/END (by name or code); DPAD_CENTER, SPACE, letters, digits and flags such as `--longpress` are refused (exit 97). Any guarded call between the tap and the text (a screencap included) ends the chain: tap, then type at once.

## Restricted serials

Only three serials get the full allowlist described above, as listed in `FULL_ACCESS_SERIALS` in `adbg.mjs`: `29f3cde9193f7ece` (Note 9 phone 1), `2ac80128013f7ece` (Note 9 phone 2) and `emulator-5580`. Any other `--serial` (a personal device, such as the maintainer's Tab S9 Ultra) runs in restricted mode, fail-closed, whatever the brief says.

- Allowed: `reverse` (with an own port) and `forward` of an own port to `localabstract:webview_devtools_remote_*`, and their `--remove`; `exec-out screencap -p --out <png>` (capture only; viewing and cropping stay governed by the brief); `shell pidof <own package>`, `shell pm path <own package>`, `shell sha256sum` of the own package's installed `base.apk`, `shell getprop` of a few read-only model/boot keys; the read-only subcommands `locate-css`, `locate-shot` and `offset`. `--own-package` and `--own-ports` still apply.
- Refused with exit 95, naming the restricted serial: `tap`, `pick`, `proc-tasks`, `input` (text, keyevent, swipe), `am`, `pm clear`/install, `svc`, `settings`, `logcat`, `install`, `push`, `pull`, `rm`, and anything else not listed above.
- `--scope-file <path>` is the only way to widen: a JSON file `{"serial": "...", "approvedBy": "maintainer", "date": "YYYY-MM-DD", "allow": ["tap", "input-text", "keyevent", "am-start", "install"]}` written from a maintainer approval. Only the listed classes open, only for that exact serial (a file naming another serial widens nothing; an unreadable or malformed file exits 2). `tap` opens the `tap` subcommand, `input-text` opens `input text`, `keyevent` opens `input keyevent`, `am-start` opens only `am start [-W] -n <own package>/<activity>` (no action, data or extras), `install` opens `install`. The normal allowlist and the typing chain still apply to what opens. Every call that reads the file logs its path and sha256 in `adb-commands.log`; the independent check compares them with the approval.
- Writing a scope file (lane A rule, 2026-11-11): only after lane A relays a maintainer approval that names the serial and the classes; quote that MC ID inside the file (an extra `"mc"` field is fine); keep each file in the run folder, never in this guard folder.
- `reverse` on a restricted serial needs both ports to be own ports (the host end decides which PC service the device reaches).
- Full-access serials ignore all of this and behave exactly as before.

Limits: it guards against accidents, not against an agent that edits its own state or log files or starts a second log; the brief fixes the log path and the independent check compares the log with the report. It cannot judge what a screenshot shows or whether a destructive target was named. The allowlist is syntactic: it does not pin settings keys, start intents other than URL data, `install`/`push` sources, logcat pids, the serial or which field a tap focused (a tap on a non-text element still grants a chain). CDP input (Input.insertText, Input.dispatchKeyEvent) and page scripts are outside the guard: briefs forbid them and the check looks for them. Coordinates come from the layout viewport, so an open keyboard or pinch zoom can still move the target; a hung or killed call shows as an intent line with no exit line, which the check reports.
