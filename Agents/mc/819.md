### MC-4630 — #819 Connections: the add flow creates `custom` connections, 2026-11-28

- Tag: decisions (maintainer via AskUserQuestion, "Compatible group, 'Custom endpoint'"; Tier 1). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#819`, `MC-3851`, `MC-350`, `MC-175`.

**What was decided.** The add flow lists a `custom` entry labelled "Custom endpoint" in the compatible group next to Reverse proxy. It takes a URL and an optional key, and several can coexist; a reverse proxy and a custom endpoint share the `allowsSeveral` rule. A new custom connection does not change the working proxy. Its stored provider label stays "Custom model" (the migration default). No stored field or `.bin` translation changes.

**Consequence.** A custom connection no longer needs a custom model first; models are added on its detail page.

### MC-4632 — #819 Connections: the test result is kept for the app session, not stored, 2026-11-28

- Tag: decisions (maintainer via AskUserQuestion, "Session-only map"; Tier 1). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#819`, `MC-3850`, `DS-046`.

**What was decided.** `connectionTestMemory.ts` holds the last result per connection id, bound to a stamp of URL and key hint; the list card and the detail page read it. It is dropped on a delete and on every successful key replace or clear (the hint can stay equal across a replace), and reads as absent once the URL or hint changes. Nothing is persisted, so no `db.connections` field is added and a stored `lastTest` stays declined.

**Consequence.** A result is lost on restart. Storing it later remains a persisted-format choice for the maintainer (Tier 2).
