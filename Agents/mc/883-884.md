### MC-4780 — #884 The Advanced custom-model editor masks the connection key like the Connections page, 2026-11-28

- Tag: decisions (maintainer ruling, Tier 1, security-adjacent). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#884`, `MC-350`.

**What was decided.** Maintainer ruling of 2026-11-28: the custom-model editor in Advanced no longer binds a field to the saved key. `SlotKeyField.svelte` (new, under `SettingsShell/connections/`) shows the same last-four chip and key-state alert as the Connections page (`hintChipText`, `keyStateText`), with Replace key (an empty masked `KeyListInput`, Save/Cancel) and Remove key (the page's `PatternWarning` confirm). A typed value exists only while Replace key is open. Writes go through `setSlotKey`, so the connection owner/clone rules and the stored shape are unchanged; no persisted format or upstream `.bin` data is touched.

**Places the key is shown (audit).** The custom-model editor (`CustomModelsSettings.svelte`) was the only field showing the key in clear text next to a masked sibling. Other fields bound to a saved key by `slotEditorValue` and left to a later ticket: `BotSettings.svelte` (`novelai.token`, no `hideText`; the other key fields use `hideText`, which masks the glyphs but still holds the key in the input value), `OtherBotSettings.svelte` (DALL-E and TTS `openAIKey`, no `hideText`; Imagen `google.accessToken`, `hideText`). The Connections page, its service rows and the add flow already show only the chip or an empty field.

**Evidence.** `SlotKeyField.svelte.test.ts` (jsdom, 3 tests) passes: chip shows `1234`, no input or attribute holds the saved key, Replace key opens an empty `password` field, Remove key blanks the key only after the confirm. Before the fix the editor rendered a `KeyListInput` holding the key, which the first test's no-input and no-key assertions reject. Real-device row: none owed (no native behavior).
