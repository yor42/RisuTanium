### MC-5090 — #929: per-task parameter mode migration, 2026-11-28

- Tag: decisions (maintainer via lane A, ticket-929 session records it). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#929`, `#156`, `MC-350`, `MC-4721`, `MC-4043`.

**What the maintainer chose.** Each of the four auxiliary tasks (memory, emotion, translate, other) gets its own parameter mode, "same as main" or "own". A saved database moves forward by the old global flag alone: `seperateParametersEnabled` on makes all four tasks "own" with their blocks untouched; off makes all four "same as main". The migration never looks at block content, so a non-empty block under flag off is kept as it is and is simply not used.

### MC-5091 — #929: `.bin` export of per-task modes follows upstream's shape, 2026-11-28

- Tag: decisions (maintainer via lane A). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#929`, `MC-774`, `MC-223`.

**What the maintainer chose.** Export translates to the upstream shape (MC-774): the upstream flag is on when any task is "own", and a task that is "same as main" gets its block written as a copy of the main values. The per-task mode is fork-only and stays in store2 and `.rtb`. A warning before export, naming what is left out, appears only when the main values cannot be represented in upstream's shape.

### MC-5092 — #929: the global flag stays as a derived compatibility field, 2026-11-28

- Tag: decisions (maintainer via lane A). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#929`, `MC-4721`, `MC-4043`, `MC-4812`.

**What the maintainer chose.** `seperateParametersEnabled` is kept, but as a derived field (on when any task is "own"); the per-task mode is the source of truth. This supersedes the parts of MC-4721 and MC-4043 that name the global switch as a Settings control: the switch is no longer a control a user sets, and the per-task choice replaces it. Where those entries say the global switch stays in Settings, read it as the per-task controls.
