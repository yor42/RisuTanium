### MC-4620 — #861 A code block with a language owns its long press and right-click; the message sheet stays on More actions, 2026-11-28

- Tag: decisions (session, Tier 1 under the ticket's own scope). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#861`, `#438`.

**What was decided.** On a gesture whose target is inside an element with a non-empty `x-hl-lang`, `ShellMessage.svelte` neither opens its action sheet from the article `contextmenu` handler nor starts the 500 ms pointer long-press timer; `observer.svelte.ts` keeps opening the code menu (Copy, Download unchanged). Both use one predicate, `codeBlockOf` in `src/ts/codeBlockTarget.ts`, so they cannot disagree. The sheet and its entries (Copy, Copy as card, Select text, Edit, ...) stay reachable from the row's More actions button (`MessageMeta.svelte`, always rendered), from a long press or right-click anywhere else in the message, and from the keyboard ContextMenu or Shift+F10 key. A fence without a language has no code menu, so it still opens the sheet. Cause: the touch long press fired the row timer and the native `contextmenu`, and every right-click reached both the row handler and the document observer, with no stopPropagation between them. No persisted format, theme-pack part or stored data changes.

**Evidence.** `ShellMessage.codeBlockMenu.svelte.test.ts`: the two code-block tests (right-click, touch hold) fail on the origin/main source and pass after; the four guards (prose right-click and hold, fence without language, More actions button) pass on both. 52 files, 745 tests of `ShellMessage*` and `observer*` pass. The Note 9 long press on a real code block is owed as a device row.
