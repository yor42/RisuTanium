### MC-4560 — #846 One helper does the Note 9 reset and census, and a clean release cannot skip an owed reset, 2026-11-27

- Tag: decisions (session, Tier 1 under the ticket's own scope; the maintainer approved the `.claude/scripts/` edit in #846). Date: 2026-11-27. Exact times: UNKNOWN. Sweep ref: none. Related: `#846`, `MC-3773`, `MC-3774`, `MC-3874`, `MC-3875`.

**What was decided.** `lease-release --clean` is refused while the grant's `resetRequired` is still true, with a message that names `workflow-device-reset.mjs`; a release without `--clean` is unchanged and keeps the obligation. The new sibling script `.claude/scripts/workflow-device-reset.mjs` has two phases for the holder of a live lease. `start` takes the census through the guard (never raw adb), classes packages as live-checks does (standing, stranded, keep-helper, `dev.risu.*` helper, vendor preinstall passed through `--stranded`, anything else a STOP before any change), runs only the allowed resets (`pm clear` when the grant owes a reset, `uninstall` of helpers, `install -r` plus `apk-readback` only when `--apk` and `--apk-sha256` are given), writes the evidence file and the baseline census under `%TEMP%` and calls `lease-reset-done`. `end` removes leftover helpers, takes the end census and releases with `--clean` only when it equals the baseline; every other outcome releases without `--clean`. The serial comes only from the grant and must be one of the two Note 9s (a constant that a test keeps equal to the guard's `PLAYGROUND_SERIALS` and the policy's `note9` pool). `INSTALL_FAILED_UPDATE_INCOMPATIBLE` (MC-3874) is not handled by the helper: it stops and leaves that decision to the PR session. live-checks and BRIEF-TEMPLATE now say "run the helper".

**Evidence.** `node --test` on `workflow-lease.test.mjs`: 40 tests pass; T29 and the changed T15 line fail on the base (a clean release while `resetRequired` was true went through). Ten mutants of the helper and controller (serial check, unclassed package, keep-helper, `io.github.yor42.*` stranded, end equality, reset-done, pm clear, clean-release refusal, owed-reset check, baseline identity) are all killed in a scratch copy. No device was used: the guard is a fake phone in the tests, so the guard's own handling of the three forms (`shell pm list packages -3`, `uninstall dev.risu.*`, `install -r`) rests on its existing tests (`device-guard/test/lease-reset.test.ps1`) and the first real use is owed a Note 9 row.
