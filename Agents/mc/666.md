### MC-4450 — #666 Preset toggle edits get the Studio save chip; three wordings chosen, 2026-11-27

- Tag: decisions (maintainer answers given to the #666 session through AskUserQuestion on 2026-11-27; exact times: UNKNOWN). Sweep ref: none. Related: `#666`, `#650`, `MC-3894`, `MC-3896`, `MC-3994`.

**What was decided.** MC-3894 ("build the chip later") is carried out: the Studio preset toggle builder shows the same saved, saving, not saved and not confirmed chip as characters and modules. Three wordings were asked and answered, each recorded here as the maintainer's own answer:
1. When the preset list is saved with another, unreadable preset, so the toggle edit is not stored, the chip reads "Save not confirmed" with Retry. It never reads "Saved".
2. When the preset is deleted, or its id becomes shared, before the covering save, the chip reads "Save not confirmed".
3. The chip is on the toggle builder only. The preset advanced form gets none in this ticket; the preset regex form (MC-3994) takes the chip from whichever of #684 and #666 lands second.
No new `en.ts` key: the existing `studioChip*` strings are reused, so no locale changes.

### MC-4451 — #666 The commit verdict for a preset edit reads the loop's standing unsavable items, 2026-11-27

- Tag: decisions (session, Tier 2, critical contract: commit verdict). Date: 2026-11-27. Exact times: UNKNOWN. Sweep ref: none. Related: `#666`, `MC-4450`, `MC-3896`.

**What was decided.** `globalApi.svelte.ts` keeps the `<scope>:<key>` set of the items the store2 loop's latest report lists as unsavable (`isItemUnsavable`), assigned first in the port's `unsavableItems`, before any notice that can throw, because the loop calls the port again only when the set changes. A preset ack settles by `presetCommitVerdict`, in this order: `unsavable` when a working config key of the preset table stands as a `settings` item (the active copy's root; Retry cannot help); `blocked` when `presets:presets` stands (the list was carried whole) or the preset is gone or its id is shared; `saved` otherwise. `blocked` reads "Save not confirmed", `unsavable` reads "Not saved" without Retry. The ack is held by a new `presetAck.svelte.ts` and reaches edits through the existing `presetAdapter.noteEdit` seam, so no history-core file (`ownerHistory.svelte.ts`, `studioHistoryService.svelte.ts`) is touched. The save loop, the codec and the persisted bytes are unchanged.

**Known limitation.** The settings check is a union over the preset table's working keys, not "the active copy at commit": a switch between plan and callback could otherwise skip a key the pass kept at its old value. While any working setting of the preset table cannot be encoded (a non-JSON value in an unrelated working field), every preset toggle edit, of the active preset or not, reads a permanent "Not saved" with no Retry; it clears at the first commit after that setting is repaired. The data is pathological and the error is on the safe side.

**Evidence.** Gate 1 plan review: three rounds (two `[REJECT]` on test design, then `[EDITORIAL]`), plan `666-plan-r3` in the session scratch. New tests and the red-on-base demonstration of the reproducers are in the PR body.
