### MC-4293 — #729: bias and biasFix are one alias group on the shared restore slot, 2026-11-27

- Tag: history-core, critical contract. Date: 2026-11-27. Related: `MC-4290`, `MC-4292`, `MC-350`.

**Decision.** `bias` and `biasFix` share one holder property (`character.bias`), so `restoreSlotOf('bias')` is `biasFix` (the last registered, `keepForeign`). Restore points, working copies and revert steps carry one `biasFix` entry whichever path wrote it, so a restore to visit start returns the start value with no false "changed elsewhere". The same-visit sticky `biasPath()` in `StudioBiasList.svelte` is removed: with the slot it flipped the write path mid-typing and split one coalesced step in two. Ordinary edits write `bias`; only the Repair step writes `biasFix`. `biasFix` is a `biasList` row with `keepForeign`; the registry header's foreign-reading wording and `parseFieldValue` (`valueMatchesKind`) already accept it.

**Consequence.** A build without the `biasFix` row refuses a restore point or step that names `biasFix` whole and keeps it aside (forward-only, MC-350). Every Studio bias edit now records its restore entry under the `biasFix` slot, so after this PR an older build refuses such an owner record. Known limitations: `typeofKind` has no production caller left (harmless); the two PRs 794 and 795 both rewrite the alias guard tests (restoreSlot T2/T3/T4 and the helper), so whichever merges second re-merges them (T3 then expects both real groups).
