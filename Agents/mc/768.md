### MC-4360 — #768 The Vertex token mint goes through fetchNative, not globalFetch, 2026-11-27

- Tag: decisions (session, Tier 2 under the ticket's own scope; the brief required the shared transport). Date: 2026-11-27. Exact times: UNKNOWN. Sweep ref: none. Related: `#768`, `MC-4185`, `MC-2965`, `MC-1451`, `MC-3070`.

**What was decided.** The Vertex token service (`src/ts/process/request/vertexToken.ts`) mints through `fetchNative`, the transport the Vertex request itself already uses, so the mint runs `assertNoSecretRef` and the proxy and native routing. `globalFetch` was rejected because every route except the proxy one JSON-stringifies the request body, so a form-encoded token request would go out as a quoted string or `{}`; fixing four shared route functions would widen the change to every `globalFetch` caller and plugin. The mint carries no native-reply ownership and no signal, so it still completes in the page before the request handoff (MC-1451). Persisted fields, the RS256 signer and encryption are unchanged.

**Evidence.** Gate 1 verified the route serialisation in `globalApi.svelte.ts`; Gate 2 round 2 is `[APPROVE]` after one substantive finding was fixed.

### MC-4361 — #768 Stale-mint caller keeps its token, the mint stays out of the request log, and invalidation also clears the reference memory token, 2026-11-27

- Tag: decisions (session). Date: 2026-11-27. Exact times: UNKNOWN. Sweep ref: none. Related: `#768`, `MC-4360`.

**What was decided.** A caller whose mint went stale (an invalidation happened after the invalidation ticket was taken) still receives the token for the request it already started, and no cache is filled. The mint is not shown in the request log (`logFetch: false`), as before. The single `invalidateVertexToken` entry now also drops the memory-only token of a `${NAME}` reference, which the two UI sites did not do before. The ticket is taken before the key read begins, because the Android vault unwrap awaits inside that read (Gate 2 round 1, F1). A non-string `access_token` now fails with `googleNoAccessToken` instead of being sent as a bearer. The JWT and the minted token are registered for redaction on both branches; the registry is never pruned and gains a few entries per mint (accepted).

**Evidence.** R1-R7b fail on base at their own assertions and pass after; svelte-check 0 errors.
