### MC-4866 — #684 S6e: regex import is strict, one step, and an over-share import is not capped, 2026-11-28

- Tag: decision (maintainer rulings asked in this session, plus a session ruling on the size cap). Date: 2026-11-28. Exact times: UNKNOWN. Related: `#684`, `S6_REGEX_SPEC.md` section 6.3, `MC-3998`, `MC-4863`, `MC-4865`.

**What was decided.** Regex import reads the file as strict UTF-8 JSON (a byte order mark is accepted), requires a top-level `type: 'regex'` and a `data` array, and refuses the whole file if any entry is unreadable or inert, naming how many failed, the first position and why. An empty `data` gives an info toast. A good file is appended in file order as ONE history step (label `import`, count N); undo removes exactly the imported rows by index and anchor and refuses `precondition` when an imported row was moved or changed. If the pane is gone after the file was picked, the import is dropped silently. Export writes the live list of the open owner (the working copy for the active preset) through the unchanged `exportRegex`, and is disabled for an empty list. Unknown keys and stages travel through import, save and `.bin` unchanged.

**Why.** A partial import would hide which rows were dropped, and a regex list has no identity to reconcile against, so refusing whole is the one outcome the user can read. One step keeps undo a single action. The maintainer chose silent drop, strict import, BOM accepted and toasts.

**Size.** No cap on the import. Measured on the desktop dev PC (best-case hardware) with 300 entries of 20 KB, across runs: record 1.1 KB after trimming, save 5-7 ms, import plan 38-92 ms (includes the parse), undo plan 24-58 ms. After a reload an over-share import keeps only the deleted items (the history store trims `done` and `restore` past its share), which `#716` may change; the test pins today's behaviour.

**Format.** No new op, record or label shape beyond `import` on the existing object-list family; the history store version stays 2.
