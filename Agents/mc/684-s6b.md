### MC-4863 — #684 S6b: regex rows are addressed by index plus the JSON the user saw, and drag reorder waits, 2026-11-28

- Tag: decision (session ruling inside the lane A batch brief, not a maintainer product choice). Date: 2026-11-28. Exact times: UNKNOWN. Related: `#684`, `S6_REGEX_SPEC.md` sections 2, 4 (D2), `MC-4861`.

**What was decided.** A regex row has no identity, so Add, Delete, Move and Duplicate address a row by its index and by the exact JSON it had when the row menu opened, with a count of identical rows then. A row that moved is followed only when it had no identical twin; with twins a changed row refuses instead of acting on the other twin. Drag reorder (spec D2) is left for a UI-only follow-up: `regexMove` already accepts a target index. Touch and keyboard reorder go through the row menu and Alt+Arrow.

**Why.** Twins are normal in this list (Duplicate makes them), and acting on the wrong twin would be silent. No new op, record or label shape: the history store version stays 2 and a reader without the regex list refuses as before; a reader with S6a's regex list applies these records unchanged.
