### MC-4590 — #864 The reset helper launches the guard of the checkout it runs from, 2026-11-28

- Tag: decisions (session, Tier 1 under the ticket's own scope). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#864`, `#846`.

**What was decided.** `workflow-device-reset.mjs` resolves `adbg.mjs` from the checkout the script itself runs from (`import.meta.url`), not from the lease root, which is the shared main checkout and can hold an older guard without `apk-readback`. The lease and grant state stay on the lease root. `guardRunner` now checks at construction that the guard file exists and, for `start --apk`, that it names the `apk-readback` verb; a failure names the path and the verb before any device call. `resetStart` and `resetEnd` accept a `spawn` seam for tests only.

**Evidence.** `node --test .claude/scripts/*.test.mjs`: 98 pass. R1, R2 and R3 in `workflow-lease.test.mjs` fail against origin/main's `workflow-device-reset.mjs` (3 fail, 41 pass in that file) and pass after. No other `.claude/scripts/*` launches the guard (grep for `adbg` and `device-guard` finds only the helper and a comment in `workflow-control.mjs`), so nothing else changed. No device was used.
