### MC-4830 — #149 stage 1: how the core of the preset field locks was built, 2026-11-28

- Tag: records (ticket session; implements MC-4811 and MC-4812, no new maintainer choice). Date: 2026-11-28. Exact times: UNKNOWN. Sweep ref: none. Related: `#149`, `MC-4810`, `MC-4811`, `MC-4812`, `MC-350`, `MC-774`, `docs/design/settings/PRESET_FIELD_LOCKS_PLAN.md` sections 2, 4, 5 and 9.

Registry `src/ts/storage/presetLocks.ts` holds the three legacy groups only (`auxModels`, `fallbackModels`, `separateParameters`); `sampling` and `reasoning` are stage 3. The accessor (`isLocked`, `setLocked`, `lockedGroups`, `nextLockList`) already honours the fork-only list `presetFieldLocks` and its reader/writer rule, so a stage-3 row only adds a registry entry. `setPreset` skips a locked group; `savedPresetFor` copies each locked group from the slot (absent when the slot has none). `presetFromWorkingSettings` no longer erases the aux models when `doNotChangeSeperateModels` is on: the callers with no slot (`appendWorkingSettingsPreset`, the `botPresetsId` repair) take the working values, and `copyPreset` still clones its source slot. The separate-parameters lock keeps `seperateParametersEnabled` too (Q6 of MC-4812), which `setPreset` previously took from the slot while locked.

Fast-forward mechanism (b): `SwitchSide` carries `locks`, picked from each page's config (`PRESET_LOCK_FIELDS`, not part of `PRESET_RECORD_FIELDS`); `cleanSwitch` replays a side's switch under the base's lock state and treats a side whose lock state differs from the base's as not clean (the existing park path). A lock toggled alone is not a preset-record change. `.rtb`: `presetFieldLocks` is a settings field with rule `arr`; `PRESET_SOURCE_FIELDS`, `presetSourceOf` and `WorkingPresetSource` carry all three flags and the list. `exportCopyOf` deletes `presetFieldLocks` so no `.bin` carries it before stage 2 adds the warning.

Five existing tests asserted the erase or overwrite and now assert the new rule: `retiredModelFlags.test.ts`, `settingsPayload.test.ts` (ii), and the Studio S4b-T8 (`StudioPresetAdvancedForm.params`), S4b-T7/T8 (`ownerHistory.presetNumbers`) and S4a-T13 (`ownerHistory.presetForm`) tests, which stage 4 would have rewritten anyway. The Studio lock notes (`studioPresetFallbackKept`, `studioPresetAuxKept`) still describe the old erase until stage 4 rewrites them. Upstream's own `saveCurrentPreset` mirror still erases, which is the stated difference.
