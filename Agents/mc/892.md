### MC-4820 — #892 Every remaining key field is masked like the Connections key field, 2026-11-28

- Tag: decisions (session, Tier 1). Date: 2026-11-28. Related: `#891`, `#892`, maintainer ruling 2026-11-28 "mask ALL other key fields like Connections does".

**What was decided.** All key fields in `BotSettings.svelte` (Google, Vertex private key, NovelList, Mancer, Claude, Mistral, NovelAI token, proxy, Cohere, Ollama, NanoGPT, OpenRouter, OpenAI, OpenAI-compatible model keys, Horde), `OtherBotSettings.svelte` (NovelAI image and voice, Stability, DALL-E, fal, Imagen, OpenAI-compatible image, WaveSpeed, ElevenLabs, TTS OpenAI, Hugging Face, Fish Audio, supa memory, custom embedding, Voyage) and `PlaygroundEmbedding.svelte` use `SlotKeyField`: a last-four chip (none for a single-secret service key), Replace key, Remove key. The saved key is never in a field. The per-character OpenAI TTS key in `CharConfigPanel.svelte` is not a connection slot, so `SlotKeyField`'s body moved into `MaskedKeyField.svelte` (hint + write callback) and both use it.

**Not changed.** Persisted shape, how keys are saved, exported or migrated: every write still goes through `setSlotKey`, and the character TTS key still writes `oaiTTSConfig.apiKey`. No new `en.ts` key, so no locale change.

### MC-4821 — Vertex token invalidation moved from typing to saving

The Vertex private key field used to clear the cached token on every keystroke; the key now only changes on Save or Remove, so `SlotKeyField` takes an `onwrite` callback and the page passes `clearVertexToken` there. Project id and client email are unchanged.

### MC-4822 — DeepL key rows and the Playground OpenAI key

The DeepL key and DeepL-X token rows in the language settings are now `custom` rows (`SlotKeyRow`, a label over `SlotKeyField`) so they are masked like the other keys; their labels stay in search. In the Playground embedding tool the OpenAI key field is a page-local copy, so it starts empty and masked (maintainer choice 2026-11-28): a typed key applies to that run only, and a blank field runs with the saved key instead of stopping the run. The saved key is never written or shown.
