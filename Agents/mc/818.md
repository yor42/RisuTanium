### MC-4430 — Memory modal: confirm, not undo, before category Delete, tag Remove and bulk re-summary Apply

Ticket #818. The maintainer chose a confirm before each of the three destructive actions in the HypaV3 memory modal (category Delete, tag Remove, bulk re-summary Apply) over an undo. Each uses the shared `alertConfirm` dialog already used by the modal's own summary delete and reset; no new component. The text names what is lost: the category name (its summaries become unclassified), the tag name, and for Apply the N selected summaries merged into one with the other N-1 removed. Cancel writes nothing and keeps the manager row or the result panel. The confirm is asked inside the action handlers, so the three buttons stay reach buttons that a theme pack may restyle but never hide (#438); no theme-pack file is touched. After the dialog closes the handlers re-check their target (the category still exists, the tag is removed by name, the held summaries still sit at the same indices) so a change made while the dialog was open writes nothing stale.
