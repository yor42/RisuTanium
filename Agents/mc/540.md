### MC-4510 — #540 Non-chat keys become connections: 13 service providers, keys only, 2026-11-27

- Tag: decisions (maintainer ruling relayed by lane A, option A). Date: 2026-11-27. Exact times: UNKNOWN. Sweep ref: none. Related: `#540`, `MC-2078`, `MC-774`, `MC-175`, `MC-350`, `MC-3074`, `MC-3076`.

**What was decided.** Thirteen non-chat key slots move into `db.connections` under their own provider ids: `elevenlabs`, `huggingface`, `fishspeech`, `novelai_media`, `stability`, `fal`, `openai_image`, `wavespeed`, `deepl`, `deeplx`, `memory_openai`, `voyage`, `embedding_custom`. `NAIApiKey` is its own provider, not merged with the chat `novelai` connection, so one folded key never overwrites the other. Keys only: URLs and models stay in each feature's settings. `hypaMemoryKey` and the character `oaiTTSConfig.apiKey` are untouched. The field count in the ticket text ("about 35") is 14 legacy fields, 13 of them migrated.

**Mechanism.** The 13 rows are appended to `GLOBAL_ROWS` after `vertexPrivateKey`; migration, `.bin` translation, key state and the unreadable-key confirm all walk that table. Readers and editors go through `serviceKeys.ts`; no reader falls back to the legacy field. A service key is one whole value (`singleKey`), never a rotation list. Fork to upstream `.bin` writes all 13 legacy fields (containers keep their sibling values); upstream to fork migrates them at load.

**Accepted limitations and follow-ups.** A key now lives apart from its feature's URL (accepted). Bare-fetch transports for some services are a follow-up. Whether the key field should mask clear text in the new row is a question left to lane A. Upstream reads the 13 legacy fields from a `.bin`, which the export fills. An older fork build reading this build's store or `.rtb` sees the service keys as unset; the connections are kept as they are, and a key typed there is absorbed again at the next V4 load. Exit path: if a use-named id is wanted later, a load step re-types the provider id (ids live only in store2 and `.rtb`, never in a `.bin`).
