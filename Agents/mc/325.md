### MC-4850 — #325: stored pack fonts and images are minted from archive views, not a per-entry copy, 2026-11-28

- Tag: implementation record. Date: 2026-11-28. Exact times: UNKNOWN. Related: `#325`, `MC-4790`, `MC-2625`.

**What changed.** `readVerifiedFile(source, pack, path, 'parts')` in `src/ts/themePack/intake.ts` returns a stored (method 0) entry as the chunks the source delivered (views of the archive bytes) and `mintMissing` in `apply.ts` builds the `Blob` from them. Nothing the size of the entry is allocated before the Blob. A deflated entry is inflated into one buffer as before. The CRC, declared-size and sniff checks are unchanged and still run on every read; the whole-archive SHA-256, the read order and the install and commit order are untouched. The default (no `'parts'`) form returns the same `bytes` as before for the icon reader and other callers.

**Invariant.** The chunks are valid only while the source's bytes are: the caller consumes them at once (the Blob copies them before the archive is released). The apply path's source is a `subarray` view of the held archive, which meets this.

**Measured** (production bundle, PC, `Agents/Tools/apply-cost`, synthetic packs; before = base `d8f812901`): byte-cap pack (249.6 MiB, 16 fonts) peak renderer RSS 744, 772, 781 MiB before and 380, 397, 441 MiB after (archive alone is about 380); apply time 1403 to 1474 ms before, 1299 to 1384 ms after (about -6%); entry-cap pack peak 462 to 469 before, 305 to 307 after. The cap was not changed.

**Owed.** Device row N9-B325: apply a byte-cap synthetic pack on the Note 9 (cold start), note time and that it applies without the renderer being killed; the diff touches the apply read path, so this row is written from the diff (MC-2713).
