### MC-4460 — #479 The Home library tile is a 4.5 rem square with the name beneath, no count and no setting, 2026-11-27

- Tag: decisions (session, Tier 1 under the ticket's own scope and MC-2931). Date: 2026-11-27. Exact times: UNKNOWN. Sweep ref: none. Related: `#479`, `#234`, `MC-2931`, `#508`.

**What was decided.** The list engine takes a tile size as `GridMetrics` (`tileRem`, `gapRem`, `fallbackRowPx`). `GRID_SMALL` is today's tile (3.5 rem, 64 px fallback) and stays the default of `gridColumns`, the drop and hit-test geometry and `CharacterWindow`, so the App host does not change. `GRID_HOME` is a 4.5 rem (72 px) square, four columns in the roughly 328 px a 360 px phone leaves, with a 108 px fallback row (100 px with a one-line name, 116 px with the two-line clamp). Only the Home variant of `GridCatalog` selects it. The tile shows the picture with the name beneath and no chat count (an archived stub holds a placeholder chat). Row heights stay measured by `CharacterWindow` and cached by row key, so a measured row replaces the fallback and `heightDeltaAbove` keeps the content under the reader still. The size is a constant, not a persisted setting: a setting is the maintainer's call and none was added.

**Evidence.** `gridHomeMetrics.test.ts` (column steps, row layout, anchor and height-delta maths, hit tests with the home metrics) fails on the base at import and passes after; the `#479` cases in `GridCatalog.restyle.svelte.test.ts` fail on the base `GridCatalog` (no name element) and pass after, with a guard that the App host keeps the 56 px tile. `GridCatalog.homeVariant.svelte.test.ts` no longer asserts identical tile classes in both hosts, on purpose. `src/lib/Others` and `src/lib/UI/Home` suites pass (195 files); `svelte-check` reports 0 errors. The Note 9 measurement (1000 synthetic characters, scroll smoothness and memory against the 56 px tiles) is not measured here and is owed.
