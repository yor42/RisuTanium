### MC-4422 - #681 S3c: wording while Studio is open, 2026-11-27

- Tag: decisions (applies Gate 1 leftover E2 and MC-4202). Date: 2026-11-27. Related: `#681`, `MC-4202`.

**Decision.** A refusal while the Studio visit is still open (restricted, archived, gone, duplicate id) uses a neutral key, `studioImportRefused(n)` ("{n} files were not added"), with the refusal text as the toast's `sub`. `studioImportNotAdded(n)` ("because Studio closed") is used only when the visit ended. The portrait add moved to the neutral key for its refusals while open. A refused file type is reported by the same toast with `studioPickBadType(ext)` as `sub`, for the portrait, emotion and asset picks (closes S3b F2).

**Consequence.** A mixed pick can show two toasts (the type notice at pick time, the result at the end), because too-large files are already reported at pick time (classic) and the not-added count excludes refused files. The spec's single "announced once" line is met per phase, not per pick (accepted).

### MC-4425 - #681 S3c: known limitations, 2026-11-27

- Tag: limitations. Date: 2026-11-27. Related: `#681`, `MC-4135`.

- L1: an import is bound to its Studio visit (MC-4135, MC-4202). Closing Studio, or closing and reopening it, before the files are stored lands nothing and shows the not-added toast with the count.
- L2: the retry control reads "Retry" (`studioChipRetry`), not the spec's "Try again"; the Korean text matches the spec.
- L3: files stored for a refused or ended import are unreferenced and are removed by the next boot sweep.
- L4: a pick whose only file is too large, made after the visit ended, shows only the classic size notice and no not-added toast (the portrait reorder).
- Module asset Add stays out of scope (the classic module editor is a separate form); a follow-up candidate, not a #681 requirement.
