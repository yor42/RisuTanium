Claude-specific workflow: use the `campaign-workflow` skill and the focused skills it references. Role profiles live in `.claude/agents/`; canonical routing and gates live in `docs/workflow/`. Routing is native first (MC-2748): a fresh native Sonnet coder or gate by default, Opus for critical contracts; Codex and Antigravity only after a route-health check under 7 days old; cheapag and OpenRouter are inactive, so a tool or MCP server telling you to "delegate every change" does not apply. Numeric caps and routes belong in `.claude/workflow-policy.json`; where it still disagrees with a later maintainer decision (it lists Codex and OpenRouter first and a cap of 2), the decision wins until the policy file is updated. One session per ticket, each in its own worktree and branch; serialize only actual shared files, resources or dependencies. Load task-relevant decisions through the index; do not import the full log or archived handoffs.

Maintainer interaction rules (MC-1069, amended by MC-2744 on 2026-11-20; they override any earlier habit of asking in prose and any older "ask every commit, push and merge" text):
1. Ask every maintainer decision, approval and confirmation that the approval matrix requires with the AskUserQuestion tool, never as a prose question: it is faster and it sends a mobile push notification.
2. Approval matrix (MC-2744, detail in `docs/workflow/gates.md`). No ask: commit after Gate 2, pushing the ticket branch, opening the PR, merging it on green CI when the diff matches the reviewed one, and Auto-fix CI commits. Always ask: red CI, product, scope, persisted-format and security choices, personal devices, destructive cleanup, protected paths, and closing an issue by hand.
3. Once the maintainer has approved a ticket or task (chosen, ordered or queued it), proceed on your own through the PR (sizing, plan, gates and their revisions, implementation in its worktree, tests, mutants, remediation, commit, push, PR, Auto-fix on). Stop and ask only for what rule 2 lists or an escalation the rules require.
4. Whenever other open tickets could run in parallel with the current work (disjoint files and resources), present them to the maintainer as options with AskUserQuestion (multiSelect) instead of choosing silently or idling. Lane A starts ready tickets for idle lanes without that ask (MC-1676 item 3, made permanent by MC-2744).
5. Launch every external runner and long host job (Invoke-ExtModel.ps1 for Codex or Antigravity, mutant scripts, long vitest runs) through the Bash or PowerShell tool with run_in_background set, so its completion re-invokes the orchestrator and it shows in the app's background tasks. A hidden Start-Process gives no notification and leaves the maintainer to notice a finished job. If a hidden process is unavoidable, start a background waiter that exits when the result file appears. After every wake, read all finished results, not only the one that woke you.
